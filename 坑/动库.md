### 早期（P0–P4.5 期间积攒，原清单这一段没有期号横幅）

- **别写悬垂 `else`**：`if (A) for (…) if (B) X; else Y;` 里的 `else` 会绑到**内层 if** 上 → 非数组分支静默什么都不做（P0 的 `valuesOf` 栽在这，单值属性一个都收不进来）
- 🔴 **还原/回滚时不要「凭存下来的内容」在旧路径新建文件** —— 快照里的 content 按**当时所在路径**记；那个文件后来若被合法搬到别处，在旧路径重建就等于**凭空复制一份**（真机还原 Inbox 时冒出一份同哈希副本）。只有本来就该在这个位置的（`moves.from`）才允许重建
- 🔴 **目录有两种口径，混了就搬错地方**：树/筛选/`文件位置` 说的是**相对库根的目录**（`00_Inbox`），而 `mover` 要**库内绝对路径**（`01_新知识库/00_Inbox`）。转换只走 `modules/notes/ops.ts` 的 `absDir()`；**自动归位那条路自己也要转**（`main.ts` 的 `runReconcile` 用 `joinPath(kbRoot, declared)`）
- 🔴 **P3 复发过一次**：`reconcile` 的计划里落点是相对库根的，忘了转就直接喂给 `mover` → 文件被搬到 **vault 根目录**下（库根之外、索引都看不见）。**纯函数用例全绿也拦不住这种错** —— 所以补的是一条**真链路**用例（造一篇 → 改声明 → 跑 runner → 断言"落在库根之下"）
- 🔴 **`processFrontMatter` 是"解析再序列化"，会把非标量值的**原文形状**改掉**：真机上 4 篇旧模板的 `创建日期: {{date}}` 是 YAML 的**流式映射**，一次往返就变成 `创建日期:` + `  "{ date }":`，**原文本再也回不去**（P2 实测）。**凡是动库前先看一遍"有没有值不是标量"**：有就整篇跳过并报出来（`services/migrate.ts` 的 `fragile` 守卫），别赌"我只改别的键"——它写的是整份前言

### P5 期（2026-09-26）新增的：库结构重排 —— 第一次"大规模真动库"

- 🔴 **`adapter.rmdir(dir, false)` 在真机上删不掉目录**（P5 真机探针抓到 + 报错原文取证）：
  平台的 `FileSystemAdapter.rmdir` 走的是 **`fs.rm`**，而 `fs.rm` 删目录**必须** `recursive: true`
  → 对空目录也抛 `SystemError [ERR_FS_EISDIR]: Path is a directory: rm returned EISDIR`。
  后果：**"还原时删掉本次新建的空目录"从 P1 起在真机上从来没成过**（还原完库里留一副空骨架）。
  ⚠️ 桩原先写的是 `fs.rmdirSync`（"删空目录"那个 API）——**比真机宽松 → 含 `newDirs` 的那两条判据离线恒绿**
  （P5 重排的还原 / 快照面板里还原一份"由 mover 建过目录"的快照）。
  ⚠️ 订正（独立审查 🟢6）：`migrate-panel` / `backfill-panel` 的 `capture()` **不带 `moves`/`newDirs`**
  → 它们的还原**根本不走 rmdir 那一段**，所以不是三条（先写成三条是"说验过但没验准"的同一类）。
  桩已对齐成 `fs.rmSync`；修法是
  "先非 recursive 试一次，EISDIR 时**再查一次还是空的**才 recursive"（别直接 recursive：
  那等于顺手删掉用户刚拖进去的东西）。
- 🔴 **`RestoreResult.notifications` 原先一处都没显示**（`snapshot-panel` / 重建面板 / 迁移面板都没读）
  —— "目录里有东西没删 / 目录删不掉 / 原位被占 / 快照内容读不回"这些**唯一**能让人察觉
  "还原不干净"的信号全静默了。现在由 **`SnapshotService.restore()` 自己弹**（与 `mover` 同一条纪律：
  服务层把"没做到的部分"说出来，别指望每个调用方记得转达）。
- 🔴 **两种目录口径又复发了一次**（P3 栽过、P5 又栽）：`plan.newDirs` 是**相对库根**的
  （`02_Areas/生活健康`），而 `mover` 要**库内绝对路径**。忘了转的症状是
  `missingAncestors` 以为整条链都不存在 → **在 vault 根下建出一个 `02_Areas/`**
  （不在库根里、索引看不见）。凡把"计划里的目录"喂给 mover，那一行必须
  `joinPath(kbRoot, d)`；判据钉在 `redline.ts` 的「`extraDirs` 必须经过转换」。
- 🔴 **同一个相对/绝对的口径错，在"断言"里同样致命**：树上「撞名 N」的计数一开始拿
  `collision.to`（**库内绝对**）去 `parentDir`，而节点 rel 是**相对库根** → 徽标一个都不亮。
  规矩：树上的计数一律走 `moves[].dirRel`。
- 🔴 **骨架里的目录必须由 mover 建**（`MoveRequest.extraDirs`），**不许面板自己 `adapter.mkdir`**：
  "本次新建的目录"是**快照的第 ③ 项**，不走 mover 就不进任何快照 → **还原删不掉，库里留一副空骨架**。
  顺带：`result.newDirs` 是"真建出来了几个"的唯一出处（日志/通知都按它说）。
- ⚠️ **本期的预览会写一条日志**（`交互规范` §6 的"落点"那一栏）：凡是断言"预览不动文件"的用例，
  都要**排除 `99_Meta/05_操作日志/`**（否则"多了一个文件"假红）；`库结构.json` 是**第一次打开面板**
  才落盘的（再排除 `99_Meta/06_工作台/`）。
- **一次 mover 调用 = 一轮一个快照 = 一个撤销句柄**（重排不是逐篇调：那样撤销要一份份来）。
  口径：**撞名逐篇跳过、不中断整批**；硬错误也继续做完剩下的；**只有快照失败才整批中止**（不自动回滚）。
- **兜底搬的笔记要把「文件位置」写下来**（`fm.setMany`）：那是这次替它做的决定，不写就没留痕，
  而且"改一次声明才搬"那条自动归位机制对它**永远不生效**。

### P6 期（2026-09-27）新增的：网格档 + 图谱（第一段）

- 🔴 **`stripExt` 不能用来处理"用户手打的名字"**：它切掉的是**最后一个 `.xxx`** ——
  把 `9.16.md` 改名成 `9.16-改`，它把 `.16-改` 当扩展名切掉，**文件静默变成 `9.md`**。
  只有名字**带点**时才现形，所以在 `mover` 里躺了整整几期。要处理用户输入时，
  **只去掉"和原文件一致的那个扩展名"**。（`stripExt` 在 `templates.ts` 生成 `[[双链]]` 那条路上是对的，别动它。）

### P6 段⑥ 期（2026-09-28）：结构与手势轮（列头槽 · 双击升格 · editor-menu · 语义色收口）

- 🔴 **`mover` **不弹撤销条** —— 弹条的是调用方**（本轮离线判据当场抓到的真缺口）：

  已抽成 **`ui/undo-move.ts` 的 `showMoveUndo(deps, res)` / `restoreNow(deps, id)`**（`ops.ts` 也改用它）——
  以后凡是"搬完要给回头路"，走这一份，别照抄。

  `mover` 里那句 `source === 'reconcile' && isPositionLocked(...)` 会把设了「位置锁定」的

### P6 段④（2026-09-28）新增的：AI 助手 + 首次使用向导

### P7.2b 轮（2026-10-04）：库框架 —— 建文件也过 mover · 「被搬空的路径」· 还原的删除次序

- 🔴 **建文件必须过 mover（`extraFiles`），且创建要排在改名之后**（P7.2b 收拢实测）：
  初始化 / 收拢要在**同名位置**建新种子页（老 `_收件箱.md` 刚被收拢搬走）——两处都栽过：
  ① "已存在 → 幂等跳过"的判定发生在计划期、老文件还没搬走 → 新种子被**静默跳过**、原位反而空了
  （症状：收拢后 `00_Inbox/_收件箱.md` 谁都没有）；② 就算建，排在 rename **之前**会当场撞名抛错。
  口径：判定认 `finalPlan` 的 **from 集合（vacated）**——"马上要空出来"不算已存在；
  创建排在改名循环之后。进快照 `newFiles`（还原删得掉，与 `extraDirs`/`newDirs` 同一条先例）。
- 🔴 **还原里"删本次新建的文件"必须排在"逆 rename"之前**（P7.2b 实测的误删路径）：
  新文件与"要被搬回的老文件"占同一路径时，先逆 rename 会把老文件搬回原位、再删就删掉了
  **老文件**（快照内容写回能救回内容，但盘上白绕一圈、还留下「还原保留」垃圾）。
  判据认**副作用**不看内容：正确顺序下 `keptAside === 0`（先删新建的 → 老文件搬回时无人在位）。
- ⚠️ **「补声明」叠着两层、口径不同、别互相套用**：
  · `mover` 第 7 步（**所有移动**的通用跟随）：**只跟"已有声明"**的笔记（把声明改到新位置；
    没声明的保持留空）——这条从 P5 起就在，**不改**；
  · `executeRebuild`：**没声明的也写** —— `area`（兜底搬）是"这次替你做的决定要留痕"（P5 口径，
    **一律写、不许加"没声明就跳过"**）；`collect`（收拢）是"每篇 `.md` 都写"（复跑重排 0 搬动的前提）。
  🔴 P7.2b 真栽过：重构时给 area 分支"顺手统一"成 mover 那层口径（declared 判空跳过）——
  A2「一键整理」那篇没声明的 Inbox 笔记声明**没留痕**，**全量套件当场红**（子集没覆盖到 A2）。
  另：只判"有声明那一篇"的收拢用例会把"只关掉 collect 那半段"的突变放绿（实测，换判"无声明那篇"才咬得住）。
- ⚠️ **收拢对 `99_Meta` 整棵除外是硬红线**：工具区里住着 `库结构.json` 自己 ——
  被收拢等于"把尺子装进箱子再量箱子"。离线与真机各有一条判据盯着它。

### P7.12 期（2026-10-07）：`T_*` 模板 YAML 的"双身份"与 Templater 路径的缺口

- 🔴 **模板文件的那段 YAML 是"两份东西"**：它贴在 `<%* … %>---` 后面、**不在第 1 行** →
  Obsidian 不把它当模板文件自己的前言（`属性规范.md` §1 口径），于是它同时是
  ①**插件读模板时的"元数据"**（buildYaml 从这里抄 类型/状态）、②**套用后新笔记的正文前言**。
  任何"改模板文件的 YAML"都会同时改**产出**——v2 迁移给 6 个 `T_*` 盖了「类型: 模板」
  （21.1 的"T_\* → 模板"），就是这个双身份的直接后果。
- 🔴 **「字面『模板』→ 按目录默认换算」有两份入口，Templater 路径漏过一份**（P7.12 收尾真机抓到）：
  · **插件套用路径**：`templates.ts` 的 buildYaml 有换算（模板来的一字面「模板」→
    `defaultsForDir`；离线 automation ② 钉着）✓；
  · **Templater 目录模板路径**：Templater 绕过插件套用、把模板原文落进新笔记 ——
    真机实测：Inbox 新建的笔记带上了 `类型: 模板`（成了"模板"）。
  修法 = `completion.ts` 的**托管分支**（`ensurePositionKey`，落笔后同一次
  `processFrontMatter` 里）补**同一份换算**；判据 automation 的「接管丙」。
  ⇒ **以后往模板 YAML 里写任何"文件级"标记，先问：Templater 路径会不会把它当产出带走？**

### P7.13a 期（2026-10-07）：空值键与引号占位符的**往返实测安全**（与 P2 的坏形状对照）

- ⚠️ **P2 那条"往返改形"的边界实测**：`创建日期: "{{date}}"`（**引号存法**）与 `状态:`（空值）
  在一次 `processFrontMatter` 往返后**逐字节不变**（真机 2026-10-07 对 `T_样例-会议记录` 实测）。
  坏的只有**裸占位符**（`创建日期: {{date}}` → 流式映射 `{"{ date }":null}`，P2 原文）。
  ⇒ 模板骨架/样例照六键写（引号 + 空值）放心；再看到"往返写坏"先问一句：**是不是裸占位符那种形状**。

### P7.14 期（2026-10-08）：空串根（整个库）的假值陷阱族 + 向导新建的族归属

- 🔴 **禁手拼 `` `${kbRoot}/` ``**：`kbRoot=''`（整个库，= vault 根）是合法配置 ——
  手拼前缀在空串下两副面孔都是静默坏：`` `${kbRoot}/x` `` → `/x`（前导斜杠，喂
  `index.get()` / 平台 API 必 miss）；`startsWith(`${kbRoot}/`)` → 恒 false
  （扫描 / 候选整片空掉）。相对↔绝对换算**只走四个既有函数**：`joinPath` / `isInside` /
  `relativeTo` / `parentDir`；范围谓词走 `inKbScope`（P7.14 把四处口径收编成一份）。
  `redline.ts` 有静态断言扫全 src（先剥注释、**保住行号**再逐行查两个形态）。
- ⚠️ **空串的"假值陷阱"族**（P7.14 逐处拔）：`if (!kbRoot)` 硬拦（AI plan）·
  `m.kbRoot || fallback`（快照还原保留目录）· `if (!out.kbRoot)` 兜底
  （normalizeSettings —— 它让空串**存不进也读不回**，是整个模式立不起来的唯一入口闸）·
  `if (!root) return false`（编辑器右键的 underKbRoot —— 整个库下**菜单整族消失**）。
  ⇒ 见到"空串"先问一句：**这里 `''` 是合法值，还是缺省？**
- ⚠️ **`relativeTo` 对"不在根下"是原样返回（不是返空）**：想判"在不在库里"必须先
  `isInside`，两个一起用，别单靠一个（P7.14 修 `rebuildNotesOf` 时的口径）。
- 🔴 **顶层"父目录"比较用 `parentDir(f.path) === base`，别用 `f.parent?.path`**：
  库顶层两边都不可靠 —— 离线桩顶层条目 `parent = null`（不建 root TFolder），
  真机平台根是 `'/'` 而不是 `''`。`foldersFor`（网格文件夹格）与「新建文件夹」的撞名集合
  都是这么栽的（P7.14 修）。
- ⚠️ **向导「新建」建文件夹 = 轻量族**（`ui/new-folder.ts` 的 `createEmptyFolder`：
  `adapter.mkdir` 直建、不过 confirm / 不进快照 / 无日志）：与 P5「骨架里的目录必须过 mover」
  **不冲突** —— 那条说的是**重排时批量建的目录**（"一次搬动"的产物，要跟那次快照一起还原）；
  "用户手建一个空文件夹"与"新建笔记"同级。为什么不过 confirm：**「下一步」就是用户的确认动作**
  （P7.14 · 用户拍板）。

### P7.14 期 · 追加（2026-10-08 下午 · 真机反馈四件）

- ⚠️ **两条"被当成外部改动"的误伤口径**（真机反馈）：
  · 「不是插件写的 = 外部改动」会误伤**用户在 Obsidian 编辑器里打字** —— 唯一可靠的预告是
    `workspace.on('editor-change')`（每次输入先发，随后自动保存才 modify）→ `vault-index.attach`
    据此记进 `writes.ts` 的**第二条登记簿**（TTL 12s，比自写那条长：编辑器保存有"停笔 ~2s"节流）。
    同步 / 别的程序不发泄预告 → 照旧标（那是这枚旗标要保的价值，别把口径放宽成"永远不标"）。
  · 测试里做对照实验前先 `clearUserEdits()` —— 登记簿有 hits 额度，第一次写把额度吃掉，
    第二次照面会**假绿**（P7.14b 的 harness 用例当场踩过）。
- 🔴 **"内容重复"的字节比较要先把 md 的正文剥出来**：新建空笔记的自动前言逐字相同，
  按整文件字节比会把"都还没写"判成"重复内容"（"保最新一份"会删掉别人的空笔记）——
  规则 = 剥前言/尾链后正文空白 → 不算重复，改走「还没写内容」行。
  ⚠️ md 判空壳要**原文**，而哈希缓存里只有 hash → md 一律重读（都很小，成本可忽略）。
- ⚠️ **枚举属性的"删键"出口别只做半边**：小窗下拉有「（空）」、右键子菜单却漏了 ——
  用户真机报"添加笔记属性后，无法手动删除"。`fm.setMany` 里 `null` 就是 `delete fm[k]`，
  UI 侧记得每处都留一个送 null 的入口（P7.14 补齐右键子菜单 + 自由值空串）。
- 🔴 **建目录要过 `vault.createFolder`，裸 `adapter.mkdir` 不进平台缓存也不发事件**
  （P7.14c 真机反馈）：裸 mkdir 建完，`getAbstractFileByPath` 查不到 —— 向导刚建完的库
  根工作台认不出来（"找不到知识库根目录"，要点一下别处等文件监视器兜底）；
  新建笔记的落点列表也看不见它。轻量族口径（不过 confirm / 不进快照）不变，
  变的只是**走平台层**这一个动作。
- 🔴 **非空文件夹的重命名/删除 = 两段式**（P7.14c）：**先过 mover**（重命名 = 整组搬 →
  快照 + 撤销 + 双链修复；删除 = `mover.trash` → 快照 + 回收站语义），**再清目录壳**
  （深→浅，`adapter.rmdir(d, true)`；清之前复查一遍别把刚被塞进来的东西带走）。
  顺序反了（先 rmdir）就是把 mover 的护栏整个跳过 —— 也别"顺手一个 recursive rmdir"了事。
- ⚠️ **删夹具用 `fs.rmSync` 后必须跟 `await app.metadataCache.settle()`**（P7.14c 实测）：
  桩的 metadataCache 有 ~300ms 滞后重解析的定时器，裸删之后它会去读一个不存在的文件 ——
  **未捕获异常直接把整个测试进程干掉**（不是某条用例红，是全崩）。照 `p713b` 的 `rmFix` 抄。
