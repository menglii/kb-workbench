### 早期（P0–P4.5 期间积攒，原清单这一段没有期号横幅）

- **`pointercancel` 在触屏上很常见**（两台设备实测共 24 次，滚动接管手势时必然发生）→ 拖动与长按都必须处理它并**干净中止**，否则卡片卡在拖动状态
- **框选/浮层起手那一帧必须先把尺寸归零到触点** → 否则会闪出上一次的残影（S4 真机实测的 bug，离线测不出）
- **触屏规则挂 `body.is-mobile`，不按视口宽度、也不看 UA** → 手机横屏 844–932px 会套上桌面密度；**S4 实测更狠**：用户平板的 UA 是 `X11; Linux x86_64`、视口 1238×731，但 `touchPoints: 5`、`pointerType` 全是 `touch` —— **UA 和宽度都与"是否触控"脱钩**
- **触屏不能用位移阈值启动拖动** → 触屏**第一个 `pointermove` 事件就带 4.5–20px 位移**，4px 阈值形同虚设 → 触屏走**长按 400ms + 10px 容差**（含三层原生长按抑制，见 `交互规格.md` §3.5）
- **顶层 `:hover` 必须就地包进 `@media (hover: hover)`** → 否则触屏点完残留悬停态
- **不给容器加 `container-type`** → 会让它成为 `absolute`/`fixed` 后代的包含块，打中"浮层从触发点展开"
- 🔴 **主题变量的别名只能挂 `body`，不能挂 `:root`** —— Obsidian 把 `--background-primary`/`--shadow-*` 定义在 `body` 上（asar 取证），挂 `:root` 时 `var()` 在那一层就解析失败 → `--surface-*` 变无效值 → **菜单/模态/卡片一起透明且没阴影**（真机第一轮用户反馈）
- **平台的 `button` 用 `box-shadow: inset 0 0 0 1px …` 当边框**、用半透明底当填充 → 只清 `border`/`background` 拦不住，会看到一圈"虚线环"
- `--background-modifier-message` 是**给平台深色 toast 用的 90% 黑**（`color-mix(in oklch, black 90%, transparent)`）→ 拿它当通知卡片底会黑底黑字
- **挂在 body 上的浮层（通知栈）在插件重载后会变孤儿 DOM** → 加载与卸载都要清（真机量到过 9 个）
- **异步移除 + `while (children.length > N)` = 死循环**：驱逐类逻辑必须按"还没开始退场的"计数（P0 的通知栈栽在这，直接把测试挂死）
- 🔴 **键盘别在模块里自己挂 keydown**：真实焦点在工作台**根元素**上，事件**不会向下**传到模块宿主 → 挂子元素的监听永远不会触发（P1 的 `F2`/`Ctrl+Enter` 就这么死过，离线也复现不出）。路由走 `ctx.keys`：`ModuleKeys.dispatch(动作)` + `dispatchRaw(表里没有的键)`
- 🔴 **`Esc` 不走 `keymap.bind`**：`Keymap.handle()` 对 escape **只问分层栈**。想接 Esc 就 `pushEscapeLayer`，而且按"有没有东西可清"**压/弹**那一层（有选中压一层"清空选择"，改名时再压一层"取消改名"）
- 🔴 **列 id 是 `prop:<属性名>`**（不是裸属性名）：默认显隐、列宽、排序 key 全用它。写成 `创建日期` 这种裸名会**静默不匹配** —— 真机症状是"默认摊开 25 列、表格 3126px 宽"（离线用例当时只断言了单列的显隐，没断言默认列数，所以没抓住）
- 🔴 **"就地改 class"的状态不能在渲染闭包里读**：卡片展开条点击时读的是渲染那一刻的 `expanded`（永远是 `false`）→ 第二次点击又送出 `true`，**永远收不起来**（症状像"点两下才有反应"）。要么读**当前 DOM 的 class**，要么整块重画
- 🔴 **属性值源的"子板块"是顶级板块**：§4.1 的原话是"板块名 = 属性值"，这个源**没有父板块**。按 `sub: true` 发出去的话，渲染层那句 `groups.filter(g => !g.sub)` 会把它们**整批丢掉**（界面一片空白）
- 🔴 **重绘路径要自己贴状态类**：`renderSection` 曾经只用 `collapsed` 决定"建不建卡片区"，
  类名交给"就地贴"那条路 —— 于是**同时改了别的字段**（走整块重绘）时，收起的板块渲染成
  "没有 `is-collapsed`、也没有卡片"的怪样子（列形态下竖条不出现）。**谁渲染，谁负责贴**。
- **同权重 CSS 规则谁生效看源码顺序**：`.kbw-cards.has-h .kbw-card-kv{flex:0 0 auto}` 与
  `.kbw-card.is-split .kbw-card-kv{flex:0 0 var(--kbw-props-pct)}` 都是 3 个类 →
  谁写在后面谁赢（实测：拖了分隔条、比例也落盘了，高度纹丝不动）→ 选择器前多挂一截父类把权重抬上去。
- 🔴 **`-webkit-box` + `-webkit-line-clamp` 会把块级子元素「压扁」而不是裁切**（c 期实测，用户截图报的
  "卡片里文字叠在一起"）：它是 **legacy flexbox**，子元素都是可收缩的 flex 项 —— 容器高度一被 clamp 限住，
  子元素就被压进那几行里 → **文字互相重叠**（真机量到每卡 3 处 `h < scrollH`，文本矩形 2–9 处真实重叠）。
  凡是"文字叠在一起"的截图先怀疑它。安全写法：`display:block` + `max-height: calc(行数 × 行高)`；
  ⚠️ `--lh-2` 是**无单位**倍数（1.45）→ `calc()` 里少 `* 1em` 整条会**静默失效**（第一版实验就栽在这，改完看着像没改）。
- 🔴 **看板有选择时，工具条整条被批量栏顶掉**（c 期起，§3.4 口径与「全部笔记」同款）→ 两条连带：
  ① 用例里"找工具条按钮"的辅助（如 `tests/specs/board.ts` 的 `gearBtn()`）**得先清选择**；
  ② 清选择**点批量栏的 ✕**，别用模拟 Esc —— Esc 走 `installGlobalEscape` 那条 **document 捕获**监听，
     桩环境里不一定接得住（c 期实测：`H.keydown(document.body, 'Escape')` 清不掉，点 ✕ 是同步生效的）。
- 🔴 **底部停靠与"通高导航"不可兼得** ⇒ `.kbw-shell` 那三个平级 flex 子元素做不到（shell 只能是 row 或 column 之一）。d2 加了一层 `.kbw-stage`（导航之外的全部 = 停靠宿主 + 主区），方向由 `data-dock` 切
- 🔴 **`data-w` 断点扣减只能"量 `root` 再减去窗格"**，不许改成量 `main` —— 那会把 152px 导航算进去，b/c 期的窄档用例会集体假红（d2 开工前就找出来的）
- 🔴 **`Esc` 分层不能靠"回调返回 false"来禁用**：`dispatchEscape()` 的规矩是"层回调返回 `false` 就把这层**弹掉**" —— 想临时不接 `Esc`（比如停靠态）必须**压/弹那一层**，否则取消之后 `Esc` 再也关不掉它
- 🔴 **`ui/dnd.ts` 的「Esc 中止拖动」要挂捕获阶段**：`installGlobalEscape`（`core/keymap.ts`）
  是 document 上的**捕获**监听，接住就 `stopPropagation()` —— 挂冒泡的**永远收不到**
  （真实环境里"拖到一半按 Esc"从来没生效过；离线上只有"Esc 栈为空"时才走到，所以一直没露出来）。
  同一节点上的捕获监听不会被 `stopPropagation()` 挡住（那要 `stopImmediatePropagation`）

### e2 期（2026-09-26）新增的几条，动到对应地方先扫一眼

- 🔴 **平台渲染器的口径 ≠ 我们的正则**（勾选框那条路）：CommonMark 里**缩进比所在清单项
  的内容列深超过 3 格**的任务行是**续行**（渲染成普通文字，**不画框**）；而**有序清单
  `1. [ ]`、引用块 `> - [ ]`** 里的任务行**照样画框**。口径一不一致，框数与任务行数就
  **永久对不上** → 老口径"对不上就不绑"退化成"**永远不绑**"（用户那篇 `9.20.md` 整张卡点不动）。
  真机上撞到"某一篇的框全点不动"先查这个；`taskItems` 现在按缩进规则过滤（**引用块那条仍是已知缺口**）。
  ⚠️ **判据只能来自真机，不能来自规格正文**：这一期照 CommonMark 规格把 Tab 改成"展开到下一个
  制表位"，真机把 `2 空格 + Tab` 那条打回来了（它**不画**，我们多收 → 整张卡只读）；
  逐条量出来的口径是 **Tab 一律算 4 格**（` 	` 画 / `  	` 不画 / `   	` 不画 / `	 ` 画 /
  5 空格画 / 6 空格不画，父项内容列 = 2）。同理"HTML 块里不画框"也是规格推断，**实测不成立**。
- 🔴 **显式清单比目录筛选更具体**：`filters.paths`（"就列这几篇"）非空时**不再过目录这一道**。
  不这么做的话，"跳过去"会落在一片**空列表**上（真机实测：快速切换跳一篇 `99_Meta` 里的笔记，
  而目录树的选择还停在 `00_Inbox`）。反过来"跳转顺手改用户的目录选择"也不对（那是持久化的偏好）。

### P6 期（2026-09-27）新增的：网格档 + 图谱（第一段）

- 🔴 **拖动落点要以"屏幕上现在的顺序"为基准，不能以"表里旧的顺序"为基准**。
  `seedOrder` 只补新来的路径、`mergeReorder` 的锚点又取表里的邻居 —— 于是
  "自动排列开着（屏幕是按名字排的）而表里是上一次自由摆放的顺序"时，拖一下会让
  **除被拖那一篇之外整片跳回旧手排顺序**。修法是先按屏幕顺序给可见项**重新落座**再并回全表。
  （§12 决策 7 明确祝福这条路径：拖一次 → 勾回自动排列 → 再拖一次。）
- 🔴 **拖动落点算完之后要显式重画一次**，别以为"拖动时 DOM 已经挪好了"：
  被拖的那一格是 `display:none` **藏在原位**的，真正移动的只是那个"虚线空位"——
  松手时把它恢复显示，DOM 就**弹回拖动前的顺序**（"我拖了，它弹回去了"）。
- **让位动画（FLIP）量几何要用布局坐标（`offsetLeft/offsetTop`），不能用 `getBoundingClientRect()`**：
  后者**含 transform**，而 FLIP 的过渡是 200ms —— 指针每 16ms 调一次，读到的是**过渡中途**的位置
  → 落点索引会来回跳、甚至偏一位。`insertionNodeFromPoint` 吃的是同一套坐标，要一致。
- **跟着光标走的"克隆体"不许继承 `.kbw-gcell` 的 `transition: transform`**：
  否则每次 `pointermove` 写的 transform 都被 200ms 过渡接管 → 浮标**永远落后光标 200ms**。
  `.kbw-gfloat { transition: none }` 一行的事。
- **"改不动就别留在那儿"**：网格档不画表格的「列」按钮；自由摆放模式下**排序下拉置灰**
  并在 `title` 里写明原因。（同一条纪律的两次应用——置灰写明或不画，别让它点了没反应。）

### P6 ② 期（2026-09-27）新增的几条，动到对应地方先扫一眼

- 🔴 **"点空白就做 X"这类判据，必须把"住在容器里的工具条"逐个排掉**：网格的排序条（`.kbw-sortbar`）
  与状态行（`.kbw-gstatus`）就在 `grid.el` 里，而它挂在 `listHost` 上 —— 只挡 `.kbw-trow/.kbw-gcell` 的话，
  **点一下「自动排列」= 清空选择**（B2 引入的真 bug，被既有用例当场抓住）。空态（`.kbw-empty`）同理。
- 🔴 **"点空白就做 X"的排除名单要包含一切"住在容器里的控件"**：网格的排序条/状态行、**表格的表头**
  （`th` 的 click **没有** `stopPropagation`，事件路径在 dispatch 那一刻已定 → 表头被重画也照样冒泡到 `listHost`）、
  列宽抓手、空态。**只补一半就是"点表头排序 = 选择被清空"**（真 bug，A 路独立审查复现）。
  规矩：**"空白"是把控件一个个排掉之后的剩余**，不是"没匹配到行/格"。

### P6 ③ 期（2026-09-27 晚）新增的：视觉与交互第二轮（用户真机 8 条）

- 🔴 **类名与"根元素上的模式旗标"撞车 = 整棵树被套上组件样式**（**长期存在**，从 P0 起，真机才逮到）：
  工作台**根元素**在键盘模式下带 `kbw-kbd`（"键盘高亮"旗标），而 `styles/components.css` 里**键帽**
  那条规则是**裸选择器** `.kbw-kbd` —— 用户一按键盘，根元素当场被打上
  `font-size: 11px / 等宽字 / 1px 边框 / padding 12px / **white-space: nowrap**`。
  最后那条**被后代继承** → **卡片摘要与小窗预览永远不折行**（用户 ⑥"预览要换行"的真根因）。
  修法两条都要：① 键帽类改名 **`kbw-keycap`**；② 会折行的容器（`.kbw-card-body` / `.kbw-cw-preview`）
  **显式写回 `white-space: normal`** —— `white-space` 是**继承**属性，别赌"没人在祖先上写 nowrap"
  （本项目在竖条那条上已经栽过同一课）。**离线测不出**：桩里没有平台样式、也没有键盘模式。
- 🔴 **`white-space` 那条的推论**：任何"我在真机上没看到它生效"的排版类改动，先**量 computed**
  （`getComputedStyle`），别对着自己的 CSS 猜 —— 上面那个 bug 的第一版就是这么被绕过去的。
- 🔴 **`.kbw-panel-actions` 从来没有样式规则**（`ui/panel.ts` 建了这个容器，样式表里没有它）：
  面板头还是**块布局**时看不出问题（两个按钮以行内块挨着），⑤ 把面板头改成 **flex 行**之后
  容器被压成 37px → **图钉与 ⚙ 竖着叠起来**（头 74px，非正文那一块厚得像没改）。
  修法：补 `.kbw-panel-actions { flex: none; display: flex; align-items: center; gap: … }`。
  **教训**：把某块改成 flex 之前，先量一遍它每个子容器的 computed `display`。
- 🔴 **"拖到另一扇窗上"的两件事必须一处加一处摘**：合并的落点观感是**整窗描边 + 顶部提示条**
  两件（WCAG/设计稿都写了），第一版**只加了提示条**、描边漏了 —— 而判据里正好有"目标窗被点亮"。
  修法：`setMergeTarget(prev, next)` 一个函数管加与摘。
- 🔴 **「动效 = 减少」时"闪一下"等于没有**：那两段现成的降级规则把 `animation-duration` 压到 **1ms**
  → `animationend` **当场触发**、动画类立刻被摘 → 用户什么也看不到。要**在 JS 里判**（`data-motion=reduce`
  / `matchMedia`）改走静态描边（`.is-flash-static` 钉 1 秒）。

### P7.2a 期（2026-10-03）：区块注册表（Region 的宿主里别放"不该被清的东西"）

- 🔴 **`Region.paint` 先清宿主 —— 宿主里不许有"重画时该活下来"的东西**（P7.2a 实测）：
  首页块容器一开始兼当 Region 宿主（块头的拖柄/⋯ 工具和内容都塞在它里面），于是
  **每一轮重画都把工具一起清掉** —— 症状很有辨识度：**不用 Region 的块工具都在、
  用 Region 的块（待处理 / 最近改动）工具凭空消失**（"点不到上移一位"），
  而且离线与真机**都不报错**（`Region.paint` 的 render 是"照画"的，没人发现少了件东西）。
  修法：内容画进**独立子容器**（`.kbw-hblock-body`），Region 的宿主是它、不是块容器。
  ⇒ 规矩：**Region 的宿主 = 专门拿来被清的那一层**；容器上的装饰件（工具条 / 角标）
  一律放宿主之外。
- ⚠️ **拖序落点在测试环境有"几何死值"**：jsdom 里 `offsetTop/offsetHeight` 恒 0 →
  `insertionRowAt` 恒判"插到末尾"。所以落点算法的判据是**纯函数多例**；拖拽用例只钉
  "起手 → 让位元素出现（gap/float）→ 松手落定 + 落盘 / 取消复原"这条**接线** ——
  别把"插到末尾"当产品行为去断言（那是测试环境的几何事实，真机由探针判 2–3 位）。
- 🔴 **抄「宿主 rect + offsetTop」那套换算时，宿主那条 `position: relative` 是写法的一部分**
  （独立审查 🔴1）：`offsetTop` 相对的是 **offsetParent** —— 网格能成立是 `.kbw-grid-inner`
  自己 `position: relative`；首页照抄了写法却漏了它 → 落点整体偏 K px（≈顶栏 + 内边距），
  真机表现为"拖了不换位 / 后面几块够不着"，而**离线永远看不见**（jsdom 全是 0）。
  规矩：**抄布局算法时，把让它成立的 CSS 一起抄**。
- 🔴 **"拆块折算间距"要把兄弟 margin 塌陷算进去**（独立审查 🟡3）：拆前 `padding + margin`
  的两笔（padding 挡着塌陷），拆后往往变成**相邻兄弟 margin**（取 max 不取和）——

### P7.2c 期（2026-10-04）：菜单移开收起 · 小窗三件 · 剪藏

- 🔴 **`pointerleave` 在触屏上是"点完必然发生"的事件**（7.1 移开收起的第一版坑）：触点没有

### P7.2d 期（2026-10-04）：首页的"真窗/真叶"块（保活 · 弱映射 · 焦点）

- 🔴 **块里停"活的"东西（真编辑器窗 / 图谱裸叶）时，Region 的 key 要按"什么会破坏现场"选**
  （P7.2d 实测形状）：「钉住的笔记」B 档的窗里是**真 CodeMirror** —— `Region.paint` 的先清后画
  会把窗节点摘出 DOM、再 `rehost` 放回去。放回去这条没问题（同一个节点换父，编辑器不重建），
  但**每保存一次打字就重画一次**就会不停摘焦点（index 每变一次 → rev 变 → 重画）。
  修法 = 那个 Region 的 key **窗口档只吃钉选清单、不吃 index**（行卡档才吃 rev）；
  另挂 `gate.onChange` 让"看板开关翻面"也触发一次重画（换档）。
  ⇒ 规矩：**Region 的 key 是"哪些变化会破坏这块的现场"的清单**，不是"照抄邻居的 rev|dismissed"。
- 🔴 **"挂了东西的块"收尾要用弱映射认"自己那一份"**（分屏双首页各认各的）：图谱裸叶与内嵌窗
  都挂在**块内容容器**上 —— 模块级单例会被乙屏的 cleanup 把甲屏的东西收掉（或反之漏收）。
  落地：`WeakMap<内容容器, 把手>`；`HomeBlock.cleanup(host)` 带宿主参数（HomeModule 从
  `mounted` 里取旧容器传给每个块）。切模块 / 块重建 / 隐藏三条路都走它，**不留悬挂叶**。
- ⚠️ **一个"✕ 之后窗不可见"的单次读数**（真机冒烟第一发）没能复现（9 次受控复现全正常）——
  登记在案，探针步骤专门盯这一形态（钉少一篇 → 窗必须还在）。

### P7.2b 轮（2026-10-04）：首页拖块"先恢复 display 再移动 DOM"（图谱卡 iframe 重载）

- 🔴 **移动 DOM 会让元素里嵌的真 iframe 重建浏览上下文**：首页拖块落位 `gap.replaceWith(box)`
  一步会把「图谱卡」里的官方图谱 iframe 重建 → 平台在 iframe load 里重建 canvas 并**当场量尺寸** ——
  那一刻 box 若是 `display:none`（原实现"先移动、后恢复 display"）量到 0×0、空白定格
  （用户报的"拖图谱块后内容消失"；被别的块位移只吃 FLIP transform、不移动 DOM，所以不坏）。
  修法 = **先把 display 恢复、再做 DOM 落位**（同一同步块，无闪帧）。判据两层：
  离线钉顺序（替 `replaceWith` 记录那一刻的 display）＋ 真机探针"拖后 canvas 非零 +
  渲染器截图异色像素 ≥500"（坏构建上当场红：0×0 + 截图直接抛）。

### P7.7b 期（2026-10-05）：动效系统化（reduce 覆盖 · 特异性账 · 探针同构）

- 🔴 **「减少动效」的覆盖有三个经典盲区**（盘点一次挖全，两段规则一起改）：
  ① **容器本体没点名** —— `.kbw-menu *` 只匹配**后代**，而菜单/浮层/模态的出场动画挂在
  **元素自己身上**（`.kbw-menu { animation: kbw-pop … }`）→ 减少动效下菜单照弹。名单要给本体一份；
  ② **插件档（`data-motion='reduce'`）只挂 `.kbw-root`** —— 菜单/浮层/模态/通知/撤销条全挂在
  **body** 上、不在 root 里 → 这一档对它们等于没开。修法 = `applyAppearance` 把 `data-motion`
  **镜像到 body**（卸载时摘，别留孤儿属性），settings.css 补 body 级选择器（点名容器，
  **绝不裸写 `[data-motion] *`**——那会打到整个 Obsidian）；
  ③ `.kbw-undobar-wrap`（撤销条）挂 body、两段名单都没它 —— 单独点名。
- 🔴 **特异性账要按 (id, 类/属性, 元素) 三列真算**：`body` 是**元素**不是类 ——
  `body .kbw-undobar-wrap .kbw-undobar-progress` 只有 **(0,2,1)**，与
  `body[data-motion='reduce'] :is(…) *` 的 (0,2,1) **打平**；打平后按源序，settings.css 在
  `STYLE_ORDER` 里靠后 → 它赢，豁免静默失效。**修法 = 链条里再加一节**成 (0,3,1)，与源序无关。
  这条**静态断言查不出**（文本都对）—— 真机探针量 computed 才抓到。
- 🔴 **探针里合成 DOM 必须与真实结构同构**：验证级联时拿合成容器量 computed 是对的
  （类名/父链与真浮层一致即可），但**父链少一节就量的是另一个选择器**——
  第一版把 `.kbw-undobar-progress` 直接挂在 `.kbw-undobar-wrap` 下（真实是
  `wrap > undobar > progress`）→ 豁免选择器不匹配、当场假红。合成前先看一眼真 DOM 的父链。
- **"到点消失型"动效的降级范式**（P6b 立、P7.7 归档）：CSS 压 1ms 会让 `animationend`
  **当场触发**、动画类被立刻摘 → 什么都没看到。凡"动画本身就是反馈"的（闪一下/光晕），
  一律 **JS 判 `data-motion`/`matchMedia` → 换静态形态**（`.is-flash-static` 钉 1 秒）。
  例外：**功能性进度指示**（撤销条倒计时）**豁免**——压 1ms 会显示成"已过期"是谎报。

### P7.7c 期（2026-10-05）：标记短词（列宽存量 · flex 挤压 · 单源守卫）

- 🔴 **改列宽默认值，存量配置会盖过它**：`settings.columnWidths` 里存过的值
  （`widthOf` 见 `ui/table.ts`）优先于列定义的 `width`；而且 notes 模块**构造时把
  widths 抄进 store、不订阅 settings 变化** → `settings.save()` 之后**不重画**（要换模块
  重建一次才生效）。两点合起来的坑（P7.7c 真机实测）：本实验库存着 `flags:60` ——
  新默认 124 一条都不生效，短词被挤成血洗。探针量"默认值几何"的正确姿势：
  **先摘存量 → 换模块重建 → 量 → 还原存量 → 再重建**（四步缺一不可）。
  另注：`table-layout:fixed` + 总宽不足时列会分到溢出余量 —— 账面 124 实测渲染 **134**，
  几何判据的"双边范围"要给余量留位（100–170 而不是死等 124）。
- 🔴 **`min-width` 会关掉 flex 的 min-content 保护 → 芯片被挤到文字血洗**：`.kbw-flag`
  的 `min-width:16px`（`⚠` 时代留的位）让窄容器里的 flex 把 2 字胶囊一路挤到 16px，
  文字溢出胶囊（实测 19/16）。**盒子级几何判据查不出这个**——胶囊盒子不重叠、格内也没
  横向溢出（scrollWidth 也是 70/70）。修法 = 胶囊 `flex:none`（按自然宽排，装不下由容器
  `overflow:hidden` 硬裁尾——截断总比糊成一团好认）。
  ⚠️ **真判据是 redline 静态**（`.kbw-flag` 基底含 `flex:none` + `nowrap`，删任一即红）：
  探针量的是**宽默认态**（有余量），那里"每枚 `scrollWidth ≤ clientWidth+1`"恒真、
  删掉 `flex:none` 也不红 —— 独立审抓到过这个"判据自证绿"的洞，别再把探针记成它的判据（`坑/判据与验证.md` P7.7c 期同名条目）。
- ⚠️ **「全仓只有一处 `.kbw-flag` 定义」的静态守卫会把作用域修饰规则也拦下**（p6d/redline
  各一条）：想给胶囊加属性（如 `flex:none`）就加在 components.css 的**基底规则**上；
  真想写 `.xxx .kbw-flag` 那种修饰规则时，先想清楚是否该改守卫（守卫的 why 是
  settings.css 同权重覆盖事故）。
- **三级节距审计的结论**（P7.7c 顺路收四笔，零改动）：页面/模块/小节三级全部落在
  `--sp-*` 刻度上；刻度外的只有两类**成体系**的：表格 td `0 10px`（全表统一、动它牵
  全部列宽几何）与 1–3px/6px 发丝档；`--sp-7`（32px）**全仓零使用**（看板板块实际用
  sp-5）—— 闲置≠混用，记档即可。

### P7.11 期（2026-10-06）：工具条"入首行"与"只重画该重画的那段"

- 🔴 **半持久元素挪进"会被清的宿主"＝下一次重画连它一起清掉，而且按选择器再也找不到**
  （P7.11 · #6/#7 实测形状）：块头工具（拖柄/⋯）入首行后住在**内容容器**里，而 Region 重画
  是"先清宿主"——一清就把工具摘出 DOM，`box.querySelector('.kbw-hblock-tools')` 从此刻起恒空
  （症状：某次索引变化后**块的拖柄/⋯凭空消失**，无报错）。修法两条一起：
  ① **留引用、画完重挂**（`paintInto` 里 `placeBlockTools(box, content, tools)`，别 querySelector）；
  ② **别拿"整清宿主"当重画手段**——局部状态切换（折叠展开/收起、换一批）只重画**该重画的那段**
  （待处理清单住进 `bodyHost`，清它不清首行；与 walk「换一批」只 `clear(list)` 同口径）。
- ⚠️ **对齐类改动：入流（flex 同排）胜过算 top 值**（批注实证「量值算得对、视觉仍偏」）：
  `align-items: baseline` 的行里，文字视觉中线与行盒中线并不重合（foot 的上 20 下 12 不对称
  padding 更让"行盒中线"本身就不是文字中线）——把工具做成**行内 flex 项**（`align-self:center`
  + `margin-left:auto`）让布局保证中线，别再用绝对定位 + 数字魔法；`padding-right:58px` 让位
  与 `:has(...) top:-2px` 一整套随之退役。
- ⚠️ **两个 `margin-left:auto` 会把空白平分**（随机漫步：换一批 + 工具都想靠右 → 换一批跑到行中间）：
  让**前一个**吃 auto、后一个只给一个固定 gap。

### P7.12 期（2026-10-07）：平台字号变量与"黑色那枚"气泡的两个真机事实

### P7.13a 期（2026-10-07）：可点作用域行 · "菜单里再开菜单"的 stay 时序

- ⚠️ **`MenuScope.submenu`（可点作用域行）的两条边界**（P7.13a · #4 落定，写代码里了、这里压成口诀）：
  ① **只认点击、不挂悬停** —— 右键菜单常常就开在光标底下，悬停即弹会让子菜单在菜单刚出现时凭空飞出；
  ② **子菜单的作用域行要剥掉可点能力**（`strippedScope`）—— 不剥就是同一份 spec 无限套娃。
- 🔴 **菜单项 run 里"收掉自己、再开一扇新菜单"必须带 `stay: true`**（P7.13a · #4 的 click-through 实测形状）：
  `fire` 的顺序是 **`run(...)` 先跑、`closeAllMenus()` 后跑** —— run 里 `showMenu` 已经把**新菜单**
  设为 `topInstance`，尾随那一下 `closeAllMenus` 会把**刚开的新菜单**当场收掉（症状：点了"没反应"）。
  加 `stay: true` 只跳过那一下（旧菜单是 showMenu 自己关的，不受影响）。**键盘路径**下

### P7.16b 期（2026-10-08）：原生属性面板那一格 —— 平台 DOM 契约面与"静默退化"

- 🔴 **契约面 = 三个平台类名，全是内部结构（不是公开 API）**（`ui/native-position.ts`）：
  `.metadata-property[data-property-key="文件位置"]` → `.multi-select-input`（那一格的输入框）·
  `.suggestion-container.mod-property-value`（平台自己的属性建议，我们开菜单时用 body 类把它藏起来）。
  2026-10-08 晚真机活体 DOM 实测。**平台升级改了结构 → 钩子失联** —— 探针有专门半步当哨兵
  （"那一格没找到 / 菜单没弹"先于用户发现）。**改这几个类名之前先看探针那步**。
- 🔴 **静默退化是结构保证，别改成"报错提示"**：认不出 / 认不出哪一篇 / 不在索引 → `return`
  什么都不做（用户拍板接受"漂了就退回平台原样"，绝不抛错、绝不破坏原生编辑）。
  `openFor` 整段 try/catch 兜底（catch 里最多把已开的菜单收掉）。
- 🔴 **焦点回环守卫：`open` 记录必须写在 `input.focus()` 之前**。把焦点还给输入框那一下
  **同步**发 `focusin` → 又进 `openFor` —— 守卫（`open?.input === input` → return）靠的
  就是"记录已写好"。顺序颠倒 = 无限递归。
- ⚠️ **监听走捕获阶段**（`document.addEventListener(type, fn, true)`）：平台对属性格的输入控件
  可能自己 `stopPropagation`，冒泡阶段就轮不到我们。用不了 `registerDomEvent`（没 options 口）→
  手动挂 + `plugin.register(() => remove)` 收。
- ⚠️ **`focusout` 收菜单别收 `relatedTarget == null` 那一档**：那是"鼠标点了不可聚焦的东西"的
  形状（点哪儿都伴随 mousedown，自有点外面关兜底）；一并收会把"点我们菜单里的项"误伤
  （菜单项是 div，点它不转移焦点 → 菜单当场没了、项永远点不中）。relatedTarget 在菜单里
  （↓ 转发过去）→ 不收。
- ⚠️ **一行 CSS 的 `!important` 不是洁癖**：平台用**行内 style** 显隐 `.suggestion-container`，
  普通规则压不住（`display:none !important` 才盖得住行内非 important 的 display）。
  类名在 TS 与 CSS 各写一遍 → 红线有静态断言钉着（两处不同源会静默半失效）。
- 🔴 **"确认流关掉时的焦点回归"会把菜单顶开一扇 —— 且离线看不见**（P7.16b 真机首跑唯一一处红）：
  `ui/panel.ts` 的模态关闭会 `previouslyFocused.focus()`，而那多半就是**那一格的输入框**
  → 一次 `focusin` → 我们的钩子又把菜单开回来（用户看到："点了「搬到」，菜单自己弹回来了"）。
  **jsdom 的焦点是假的**（合成 click 不转移焦点、contenteditable 的 focus() 也不生效）——
  离线判据**永远看不见这一类**。修法 = 动作**在飞期间**（确认 → 搬 → 补声明没跑完）不放行重开
  （`actOn` 记"哪一格在干活"，`.finally` 放行）—— 离线判据用"模态还开着时补派 focusin"模拟那一拍。
  口诀：**凡是"删掉之后不许自己回来"的浮层，都要问一句"谁会在事后把焦点还回来"。**

### P7.21b 期（2026-10-11）：**菜单默认抢焦点 —— "输入框里的命令菜单"两类闸门都盲** · **`keepFocus` 口子**

- 🔴 **① `showMenu` 开菜单必 `root.focus()` —— "在输入框里打 `/` 弹菜单"这种用法会被它打死**：
  焦点一被菜单拿走，用户继续敲的字全落进菜单根（非可编辑元素 → **不派 `input` 事件**）——
  "继续打字就地过滤"在真机上根本做不到（现象：一个字一次点击；点回输入框那下又因"点菜单外"把菜单关了）。
  ⚠️ **两道闸门都验不到它**：离线用例与探针的"打字"都是**程序性改值 + 派事件**
  （`input.value = …; dispatchEvent(new InputEvent…)`）——绕开了真实键盘路径；
  jsdom 里 `document.activeElement` 是**能看出来的**（本轮独立审实测 `activeElement = .kbw-menu`），
  但没人想到去断它。⇒ 判据要么断 `document.activeElement === 输入框`（离线可断），
  要么在探针里直接盯 `activeElement`（行为路径验不出来时，就盯状态本身）。
- ⚠️ **② 修法是"菜单加口子"，不是"菜单别抢焦点"**：`MenuHandle` 的 `root.focus()` 是**键盘导航的载体**
  （root 上的 keydown 管方向键/Enter，多数菜单要它）。本轮加的是 `MenuSpec.keepFocus?: boolean`
  （默认 false = 老行为一个字不变）：开了它的菜单不调 `focus()`，**Esc 照常管用**
  （走 `pushEscapeLayer` 的文档级栈，与焦点无关）、**选点靠鼠标**；代价 = 这扇菜单没有方向键导航
  （对"过滤式命令菜单"是合理取舍 —— 过滤靠打字、选中补一条"Enter = 选第一项"接在输入框自己的 keydown 上）。
  ⚠️ `normalizeSpec` 是**白名单式重建**（`return { scope, items }`）—— 新字段要在那儿**显式带过去**，
  不然口子静默失效（本轮差点栽这；`tests/specs/menu.ts` 管菜单硬规矩，新字段的口子记得配判据）。
- 💡 **③ 顺带的口径**：菜单项 `run` 里让调用方 `input.focus()` 把焦点还回去（鼠标点选后焦点会落 body）——
  "选完接着打字"这条链才算闭合。
