### 早期（P0–P4.5 期间积攒，原清单这一段没有期号横幅）

- **`Region`（区域重绘）的宿主元素必须就是被清空的那个容器** → 挂错一层（比如把 `.kbw-nav` 当宿主，而渲染写进它的子元素）会在重绘时把子容器一起清掉，**症状是那块永远是空的**（P0 真踩过）
- **`data.json` 里的"还没选过"要用 `null` 表达**，别用 `[]`：`[]` 是"用户显式全开"，两者混一起就会被旧默认值顶掉（真机踩过：上一版把 `[]` 写进了 `data.json`，新版默认再也回不去）
- **`repaint()` 不要 `paintAll(true)`**：模块自己会写界面偏好（排序/列宽/树展开），设置一落盘就绕回来重建整个模块 → 选择/筛选/树展开全丢。三个区域的 key 已经够用了
- **`Debounced.flush()` 不带参就是"执行挂起的那一次"**（没有挂起则什么都不做）：收尾场景（模块卸载前存配置）用它对
- 🔴 **顺序表/映射表的迁移要挂 `vault.on('rename')`**，别挂"改名那个按钮"：改名有四个入口（悬浮小窗 / 笔记菜单 / 表格 / 跨板块拖动），挂按钮必漏一个；而表里存的是**路径**，漏一次的后果是那篇笔记从手动顺序里失联、掉到末尾
- 🔴 **`ConfigFiles.write()` 原先不通知订阅者**（写完后 cache 与文件一致 → 防抖那一轮判成"没变"）→ 已改成也走 `emit()`。教训：**"写完等别人自己变"这种写法不成立**，同一份配置的另一个入口（设置面板/模块）不会知道
- 🔴 **"这个东西比模块活得久" ⇒ 一切挂在模块上的东西都可能过期**（d2 查出的真缺陷）：看板面板是跨模块存活的，而它订阅的是 `deps.cfg` —— **那一个** `BoardConfigStore` 实例。切走模块再回来，模块是新的、带一个新 store，**旧 store 的 file watcher 挂在旧模块的 Disposer 上、随模块一起收了** → 旧 store 从此再也不 `emit` → "换停靠边 / 钉住 / 切档"这些写配置的入口对它全都失聪（症状：面板好端端停在那儿，你从菜单换了边，它纹丝不动）。修法是 `rebindCardPanel(deps)`（换 deps + 重订阅 + 补做一遍），挂在模块的 `mount()` 与 `reloadCfg()`。**以后再往长寿对象里塞依赖，先问一句"切模块之后它还有效吗"**
- 🔴 **`BoardConfigStore.load()` 读完不 `emit`** ⇒ "配置就绪"这件事只有 `reloadCfg()` 知道。于是**在 `mount()` 里按 `cfg.get()` 重排会按到默认值**（d2 实测：切模块回来窗格当场被卸掉）。要重排就先问 `isLoaded()`
- 🔴 **`ctx.xxx` 是单槽，多个视图 = 后开的胜**（d2 抓的）：`ctx.dock` 被后开的工作台标签覆盖，
  于是"比模块/视图活得久"的东西（看板面板）若**每次从 `ctx` 现取**依赖，就会申请到**别人那一份**上；
  而视图 `onClose` **无条件清空** `ctx.xxx` 会让**还活着的那个视图永久失效**。
  规矩：长寿对象**认一次依赖、用到底**；视图收尾**只撤自己的、把口子交还给还活着的那个**

### e 期（2026-09-26）新增的几条，动到对应地方先扫一眼

- 🔴 **`Region.paint()` 是「先清宿主、再调渲染函数」**（`core/store.ts`）→
  凡是"**拆之前得先记点什么**"的逻辑（滚动位置、展开态、光标…）**必须写在 Region 之外**
  （store 订阅里），写进模块渲染函数（`paintModule` / `paintBoard`…）里就是**往一个空容器上记**。
  ⚠️ 阴的是它**不报错**：视图记忆第一版就这么写的，捕回来一片空，
  又被"捕获为空不覆盖"那条守卫**静静吞掉** → 症状看着像"功能压根没生效"。
- **停靠宿主的"口子"是单槽**：两个占用者（编辑面板 / Peek）谁都能把对方收掉 ——
  ① `request(null)` **不认人**（"我不是占用者"时**别去碰它**）；② 让出之后要能**收回去**
  （`modules/board/window-seat.ts` 那一声喊，⚠️ 听者挂**模块**上，因为被挤走的那个对象会被整个销毁）。
- **真机上"有滚余量"的容器未必是你以为的那个**：实验库里是**看板的列**（列形态每列各自滚），
  而看板体与笔记列表都是 0 → 视图记忆必须把**列**也贴上 `data-scroll`。
- 🔴 **单槽资源要"认人"**（e 期独立审查的 3 条 🔴 全出在这上面）：停靠窗格只有一个，而它从 e 期起有
  **两个占用者**（编辑面板 / 预览窗格）。凡是"我不要了 → 让出来"的收尾**都必须先问身份**
  （`ui/dock.ts` 的 `DockOwner`）—— 不认人的 `request(null)` 会把**别人**正占着的窗格一起收掉。
  同理，"开一个收另一个"不能靠在第三处顺手判一下（那种写法必然漏掉某条入口）。
- 🔴 **"打算占" ≠ "此刻占着"**：被抢走的那一瞬间 `isDocked()` 是 false，而它**仍然打算**占着
  （下一次配置变更就会再申请一次）。拿后者当"该不该让它让位"的判据 → **没人收它**，
  它转过身又把窗格抢回去（离线实测：预览刚开起来就被关掉）。
  判据要用**意图**（`面板开着 ∧ 配置说了停靠` = `panelClaimsWindow()`）。
- 🔴 **`applyScroll` / `captureScroll` 要连 `root` 自己一起算**：`querySelectorAll` **不含自己**，
  而调用方常常正传着那个带 `data-scroll` 的元素（看板传 `.kbw-board-body`、外壳兜底传 `.kbw-modhost`）
  → 那两个键"捕得到、写不回去"，而红线里那条"三层缺一不可"的注释**白写了**。
- **"放不下"必须是几何事实**：`applied === false` 有两种原因（容器放不下 / 此刻被别人占着），
  拿它去弹"放不下"的通知会在**1400px 宽**的工作台上弹一条假的。要问就问纯几何的
  `port.canHold(where, size)`。
- 🔴 **`querySelectorAll` 不含自己**这条在**断言**里同样致命（见上一条）：判"容器里有没有东西"
  要 `directChild` / 显式挑掉 `.kbw-dock-grip`，别用"宿主有子元素"这种恒真的说法。

### e2 期（2026-09-26）新增的几条，动到对应地方先扫一眼

- 🔴 **"重绘"会把滚动位置清零，而它不报错**：`Region.paint()` 先清宿主 → 新画出来的 DOM
  每个 `scrollTop` 都是 0。症状是"**我勾一下勾选框 / 同步写进来一笔，看板跳回顶上**"
  （真机量到：列 80 → 0、卡面正文 200 → 0）。修法是"捕获在清之前（store 订阅里）、
  写回在**画实那一趟**"，并且 **`restoreIfReset`：只写被清零的那些** ——
  捕获与写回之间隔着一次异步重读（`ensureTexts`），用户在这中间自己滚过的不许抢。
  ⚠️ **只保"索引变动"引起的重绘**：搜索/筛选/形态变了的重绘**本来就该回顶上**。
- 🔴 **"还保不保滚动"的判据必须与 `Region` 的 key 同源**（e2 独立审查 🔴1）：第一版写的是
  "`rev` 变了且 `cfgRev` 没变"，而 key 里还有 `renamingNote`（后来还有 `paintRev`）——
  **两个集合不一致** → `F2` 进就地改名再 `Esc`（一个字节都没改）就把滚动位置清了。
  规矩：**默认保**（把 key 里"内容/瞬时态"那几个字段抹平再比），只有"视图参数真变了"才不保；
  另外"请重画一次"要用**专属字段**（`paintRev`），别借 `cfgRev` —— 借了就等于告诉判据"视图参数变了"。
- 🔴 **捕获与写回要在同一个同步块里**（e2 独立审查 🟡2）：看板是**异步**画的，跨趟快照必然撞上
  "重绘中途的空壳"（卡暂时不在、`scrollTop` 全 0）—— 那份全 0 的快照会**盖掉**好快照，
  症状与"跳回顶上"一模一样。正确形状：`paintBoard` 里"捕 → 清 → 重建 → 写"一气呵成
  （`Region` 那边配 `reuse: true`，别让它先清）。**表里存路径的（`card:<板块>:<路径>`）还要跟着
  `vault.on('rename')` 迁键**，并在改名那一刻就地钉下位置 —— 改名那一下索引会有一趟画不出那张卡。
- **"打算占" ≠ "此刻占着" / 单槽资源要认人** 这两条 e 期已经写过 —— 这一期又用在了别处：
  跳转的"让她看得见"要等**画完**（展开会触发重绘），所以意图只记在 `pendingReveal` 上，
  由 `paintBoard` 末尾执行；**滚动恢复排在它前面**（"保持你原来的位置"服从"你刚要求去别处"）。

### f 期（2026-09-26 晚）新增的：多悬浮窗 · 每篇小窗设置 · 字号 · 尾链折叠

- 🔴 **`emit()` 是"先拷一份订阅者、再逐个叫"** → **同一次配置变更里被收掉的那个对象，它那条已退订的
  `onCfg` 仍会被叫到一次**。单例时代看不出（收了就是没了）；长寿对象有 N 个实例之后非常实在：
  被收掉的那一扇照着配置**再申请一次窗格**，把刚拿到窗格的预览顶掉（症状：预览开起来、转身就被关掉，
  而"抢窗格"的那扇窗**根本不存在**）。规矩：长寿对象的每个回调**先问一句"我还活着吗"**
  （`panels.has(p)`，与 `ui/panel.ts` 的 `didClose` 同一条纪律 —— 别拿 `isConnected` 之类间接信号推断）。
- 🔴 **单槽资源的占用者身份要带实例号**：面板从单例变成 N 个实例之后，`'panel'` 这个字面量
  **对每一扇都为真** = 等于不认人（e 期那条 🔴 换个入口复发）。改判 `panel#<n>`（`ui/dock.ts` 的
  `panelOwner()` / `isPanelOwner()` 是唯一出处，别手拼字符串）。
- 🔴 **"状态层改成 N 个实例"之后，收尾层一定还留着"只有一个"的旧假设**（f 期独立审查一次抓出 4 条）：
  · `closeCardPanel()` 是**逐扇遍历、每扇都 destroy**（给模块卸载 / 视图关闭用的）——
    "这一扇不要了"必须调 `destroyPanel(本扇, …)`。**在甲窗点「完成」而乙窗也没了**就是这个（4 条路一起漏）；
  · `document` 上的"点外面"监听**按注册顺序跑**：先关掉的那扇会改掉"最近交互"，
    后面那扇读到的就是改过的值 → 判据失效。**"这一发事件该关谁"要在捕获阶段先快照下来**；
  · "最近交互"与"**最后建的**"在只有两扇、且点的是后建那扇时**天然重合** ——
    只测那种例子时，把 `raise()` 的层重排整段删掉都照样全绿（f 期 20 条用例的实测）。**判据要挑"先建的那扇"**。

### P5 期（2026-09-26）新增的：库结构重排 —— 第一次"大规模真动库"

- **视图记忆里"以路径结尾"的键要跟着 rename 走——挂在插件层**（`main.ts` 的 `vault.on('rename')`，
  不是看板模块里）：重排是从「全部笔记」发起的，那一刻看板**没挂载**、它自己的 rename 处理不在场，
  `card:<板块>:<路径>` 全成死键 → 切回看板**整片滚动位置重置**（用户会当成重排的 bug）。

### P6 期（2026-09-27）新增的：网格档 + 图谱（第一段）

- 🔴 **多写入方的配置，模块里不许存副本 —— 只读 `settings` 现取**。
  网格的「自由摆放顺序表」有两个写入方：① 网格自己（拖动换位）；② **插件层**的
  `vault.on('rename')`（改名迁键，挂 `main.ts`）。模块里再存一份的话，②改的是 settings、
  **副本不会跟着动** → 下一次渲染用旧表算顺序 → 那篇刚改名的笔记在表里查无此路径 →
  被当成"没摆过的新笔记"**掉到末尾**（症状像"改个名位置就乱了"）。
  分界线：**单写入方的留在 store（它变要重画），多写入方的读 settings**。这是本轮用例逮到的真缺陷。
- 🔴 **`Store.set()` 对"值全等"的 patch 直接 `return false`（不通知）** →
  `repaint()` 借 `rev` 时，"索引没动但要照新状态重画"这件事**一声不响地什么也不做**。
  要有**专属字段**（`paintRev` 自增一位），e2 那条纪律的机制根因就是它。

### P6 ② 期（2026-09-27）新增的几条，动到对应地方先扫一眼

- 🔴 **改了默认值 ≠ 生效**：存量 `看板配置.json` 里那个 `"panelProps": "few"` 是**旧默认被物化**下来的
  （`normalizeView` 给每个键都落一个具体值），只改常量对**任何打开过看板的库一点效果都没有**。
  要按**版本号**做一次性迁移（`BOARD_CONFIG_VERSION` + `migrateLegacyView`）。
  ⚠️ 迁移**只在读盘那一个入口做**（`BoardConfigStore.apply`）—— 写入口的入参是用户**刚选的**值，
  在那儿迁移等于"选了等于没选"。⚠️ 同一个坑的另一面：`panelFont: 0` 这种"0 = 没设过"的哨兵
  改语义**天然生效**（存量文件里存的就是 0），**没有哨兵的值才需要迁移**。
- 🔴 **`notesIntent` 这类"一次性意图"消费掉就要清**（`consumeIntent()`）：去重只在本实例里靠
  `lastIntentSeq`，**模块一重建**（切走再回来）新实例就从 0 开始 → 把上一次跳转**再放一遍**
  （症状：用户点过「还原显示」，去别处转一圈回来，筛选与预选中一起复活）。
  ⚠️ **写回归用例时别用 `ctx().goNotes()` 切回来** —— 那一次调用自己会把意图清成 null，**等于替实现把 bug 盖住**
  （第一版用例就是这么假绿的；要点导航项才是真路径）。
- 🔴 **改默认值 = 改常量 + 迁移存量 + 钉住"接线"**，三件事缺一不可：
  ① 常量（`BOARD_VIEW_DEFAULTS`）；② **按版本号一次性迁移**（`migrateLegacyView`，只在**读盘**那一个入口做）；
  ③ **静态钉住"读盘入口真的调了它"**（`redline.ts`）—— 否则把那次调用删掉全仓库照样绿，
  而老用户的 v1 配置**永远停在旧默认**。⚠️ 纯函数有判据 ≠ 接线有判据（B 路独立审查实测）。

### P6 段⑥ 期（2026-09-28）：结构与手势轮（列头槽 · 双击升格 · editor-menu · 语义色收口）

- 🔴 **`ctx.xxx` 单槽"认人"只做在视图层是不够的 —— 本轮第三次复发**（独立审查 A🔴1，有复现）：
  `ctx.colSlot` 与 `ctx.dock` 一样是**单槽**（多标签时后开的视图胜）。给视图加了
  "收尾只撤自己的、把口子交还给还活着的那个"之后**仍然不够** —— 因为**模块是在
  `mount()` 里认依赖的，而每次切模块模块都会重建**：分屏两个工作台标签、都停在「全部笔记」时，
  两边模块**都会**从 ctx 现取 → 拿到的是**后开那个视图**的槽 → 两个模块往同一个槽里
  `replaceChildren` 互相顶掉 → **先建的那个视图的「目录」标题彻底消失**（槽里空、树里也空）。
  **修法是"渲染谁，谁把口子摆成自己的"**：`paintModule()` 在调渲染函数**之前**
  `if (this.myColSlot) this.ctx.colSlot = this.myColSlot`。
  ⇒ **规矩**：任何进 `ctx` 的**单槽资源**，都要在**渲染点重新认领**，不能只依赖
  "开视图那一刻写进 ctx"。"外壳知道自己是哪一扇，模块不知道 —— 那就别让模块去猜。"
  ⚠️ 连带：**"清掉 `ctx.colSlot` 再切模块"就再也造不出"没有槽"的世界了** ——
  那条兜底判据得改成**直接渲染模块**（`renderNotes(bare, ctx)`）才够得着。

### P6 段④（2026-09-28）新增的：AI 助手 + 首次使用向导

- 🔴 **`configs.ensure()` 会写盘，`read()` 才是只读**（独立审查 A🔴1，**真缺陷**）：
  `ensure` = "不存在就把默认值写下去 + **mkdir 祖先**"。向导第 3 步号称"只读"却调了它，
  于是**在用户刚敲进去的那个库根下凭空建出一整棵 `99_Meta/06_工作台/`**
  （`workbenchDir()` = `<kbRoot>/<metaDir>/06_工作台`，而第 1 步正是让用户改库根的地方）。
  ⚠️ **四层判据原来全都看不见它** —— 离线只 hash `.md`（那是 `.json`）、探针只数
  `getMarkdownFiles()`、红线只查裸写 API（`ensure` 是合规封装）、**真机实验库里那个文件本来就存在**。
  ⇒ **凡"这一步只读"的判据，两件事缺一不可**：① 覆盖**全扩展名**（路径清单 + 内容各一份）；
  ② **在真能现形的场景下跑** —— 探针那一步要**先把 kbRoot 挪到子目录**再跑，
  否则在"配置文件本来就存在"的库上**恒绿**。
- ⚠️ **"拦下要说出来"也适用于"解析阶段的丢弃"**：`parseAdvice` 原先把缺 `path`/`to` 的
  建议**静默丢掉**，而 `buildAiPlan` 的 `blocked` 是一路带到界面上的 —— 两种丢弃口径不一致。
  现在 `AiAdvice.dropped` 也计数并显示。
- ⚠️ **两处各截一刀 = 实际只剩一半**：`AiService.ask` 按**轮**截 history、`buildMessages`
  又按**条**截一次 → "最近 3 轮"实际只有 2 轮。口径只留一处（谁拼消息谁负责喂多少）。

### P7.2d 期（2026-10-04）：把手会变"死"——`WeakMap` 存的长寿引用要有验活

- 🔴 **"块外"的路能把块里的东西收掉，块却不知道**（独立审 F2）：首页块用
  `WeakMap<宿主, 把手>` 认自己那扇内嵌窗；而窗可能被**别处的路**收走（另一扇窗把它
  最后一篇 tab 搬走 → 内嵌窗被搬空 → `destroyPanel`）。块抱着**死把手**时
  `rehost()/sync()` 全是 `!panels.has(p)` 早退 —— **静默空转**：块里剩一个 400px 空框，
 且只有块重建才自愈（重画压根不触发重建）。
  修法 = 把手加 **`isAlive()`**（问"我还在不在注册表里"），`paint` 拿到把手**先验活**、死了
  就 `windows.delete(host)` 重开一扇。判据把"块外搬空 → 重画 → 块里重新有活窗"整条走了一遍。
  ⇒ 规矩（与 d2 的 `didClose` 同一条家族）：**长寿引用存的是"可以死"的对象时，
  用它之前先问显式状态**（注册表里还在不在），别拿"引用还在"当"它还活着"。
- ⚠️ **多屏共用一份数据 + "谁抢谁搬"的语义会变乒乓**：分屏两个首页都渲染同一份钉选时，
  A 块建窗 → B 块把 tab 搬进自己 → A 重建时再搬回 —— 两块交替空框。
  修法 = 抢（`adoptTab`）只对**浮层/窗格**成立，**内嵌窗之间先到先得**（后到的显示"没抢到的"，
  极端情况为空 —— 边缘布局，记档接受）。⇒ 给"全局唯一资源"（一文件一编辑器）加新的展示位时，
  先想"两个展示位同时开着会怎样"。

### P7.13b 期（2026-10-07）：**索引只跟 `.md`** —— 非 md 变化不动修订号，按修订号缓存的一切都会陈旧

- 🔴 **`vault-index` 的事件链只认 `.md`**（`inScope` 卡 `.md`）：往库里放/挪/删一张 `.png`/`.bin`，
  **`revision` 不涨、不发变更通知** → 两件连带一起犯：
  ① **维护三件的缓存不失效**（`computeMaintenance` 的 key = `kbRoot|revision|exclude`）→
  「N 组重复 / N 件孤儿」那行**不消失**（真机实测：E3 挪完孤儿、E2 清完重复，行还挂着）；
  ② **区域不重画**（home Region 的 key 也吃 `revision`）→ 屏幕上那行也不走。
  修法 = 这两条链（重复保一份 / 孤儿挪待清理）收尾**主动 `ctx.index.rebuild()`**
  （+1 修订号 + 发通知，顺手把 repaint 也推了）。**日志写盘会顺手 bump 一次**（操作日志是 `.md`）
  —— 但它有失败支（写不进就不 bump），且晚 120–450ms，别把它当唯一守卫。
  ⇒ 以后凡"动的是非 md、行/缓存却要跟着变"的功能，都按这条办：**动完重扫一次**。

### P7.16 期（2026-10-08）：脏检查重画的"三件套"——两条触发源 · 闸门 · 让着焦点

- 🔴 **长寿面板订阅"库变化"的落地形状**（P7.16 · #1，`modules/board/editor.ts` 的 `createPanel`）：
  ① **两条触发源各管一摊**：`ctx.index.onChange` → 属性/条目变了（外部改 YAML、同步拉进来、

  `getAllLoadedFiles().length`（与 P7.15 给目录树加的那一枚同源）判"库变了"再重画全部 tab。
  ⚠️ **目录"改名/移动"不在触发源里**（改名既不加也不减计数、指纹不变）——低危、**记档**：

### P7.24 期（2026-10-11）：**数组做重绘 key —— `join(',')` 与空串成员碰撞（`[]` vs `['']` 同 key）**

- 🔴 **`[].join(',') === [''].join(',')`（都是空串）** —— 树 Region key 里
  `open` / `treeShowFiles` 原先 join 进 key，而 P7.24 · T2 让 `''`（库根）成了 `open` 的
  **合法成员** → "全部收起（`open: []`）→ 点根 caret 开回来（`open: ['']`）"这一对状态
  **key 相同、不触发重绘**：设置里已经开了、DOM 停在收起态（"点了没反应"又一种新形态）。
  ✅ 修法 = key 里改 `JSON.stringify`（`'[]'` vs `'[""]'` 可分）。
  ⇒ **规矩**：数组进 key / 缓存 / 比较时，**元素可能是空串（或任何能 join 出歧义的串）就上
  JSON.stringify**；`join` 只在"元素保证非空、且顺序无关无所谓"时用。
  同类自查问句："这两个不同状态 join 出来会不会**同一串**？"
  （判据：`tests/specs/p724.ts` 的 T3 用例 + 突变 M2 —— 换回 join 当场红。）
- 🔴 **`ConfigFiles.read()` 对"文件在、但 JSON 坏了"会静默退回 `defaults()`**（P7.24 · #12 自查处）：
  调用方拿到的是一份**默认值的假象**（如"0 个目录"），与"文件缺失"分不开。⇒ 需要**如实三态**
  （存在/缺失/坏）的读方，走 `exists()` 判缺失 + **直读 `vault.read` 自解析**（坏 JSON 当场抛 →
  自己 catch 说"读不出来"）；`configs.read` 保留给"缺了就按默认渲染"的既有场景（谁用谁知道）。
