## 一、坑单搬入（P0–P6，按原顺序）

### 早期（P0–P4.5 期间积攒，原清单这一段没有期号横幅）

- `Plugin.saveData` **静默吞 ENOENT** → 写前 ensureFolder 或写完回读
- `fileManager.renameFile` **撞名时平台会抛 `Error: Destination file already exists!`**（**不覆盖，不丢数据**，S2 实测）→ 但**仍要自查**：为了区分「已搬过（sha256 相同）」/「真冲突」，以及逐篇 skip 不中断整批。另外它**就地改 `file.path`** → 取名前先捕获旧路径；目标目录不存在会抛 ENOENT → 先 mkdir
- `fileManager.trashFile` **读 `trashOption` 分流**且不弹确认；**真值只有 `system` / `local` / `none`**（S2 从 asar 取证）→ 只有 `local` 能程序化拿回（`.trash/` **扁平存放**）；传个未知值它会**静默什么都不做**
- **双链是平台自动改的**（`renameFile` 返回那一刻已改完，三种写法全覆盖）→ 不用自己写修复；但快照要在 **rename 之前**用 `metadataCache.resolvedLinks` 反查引用者存下来
- **平台没有多选控件** → `文件位置` / `平台` / `tags` 这些列表属性，多选必须自研
- `vault.adapter` 写完 **`getAbstractFileByPath` 立刻可见，但 `metadataCache` 要 ~300ms** → 还原文件后别立刻读 frontmatter
- 🔴 **`Plugin.addCommand` 会自动给命令 id 加插件 id 前缀** → 自己再写一遍就变成 `kb-workbench:kb-workbench:open`，`executeCommandById('kb-workbench:open')` 找不到（真机探针抓到；离线桩也必须模拟这个前缀，否则假绿）
- 🔴 **`getLeaf(false).openFile()` 会替换当前叶子** → 当前叶子常常就是工作台 → **一开笔记，工作台那一页就没了**（P3 真机实测：探针后面十几步全在"容器宽=0"上失败）。要从工作台里打开别的笔记一律 `getLeaf('tab')`（新标签）
- `MarkdownRenderer.render` **第 5 参必须是 Component** → 否则核心从插件栈帧报内存泄漏告警
- 🔴 **悬浮小窗挂真编辑器（P4 实测）**：配方是 `new WorkspaceLeaf(app)` + `setViewState({type:'markdown', state:{file, mode:'source'}})` 再把 `leaf.view.containerEl` 挂进自建容器。四件事：① `@types` 里 `WorkspaceLeaf` 的构造函数写成 **0 参**（与实际不符）→ 要 cast 构造函数，别为了过编译把 app 丢掉；② 挂上去的 `containerEl` 自带 **`.view-header`**（一整排导航条）**和 `.metadata-container`**（前言面板，属性行就在窗外那一排，同一件事不能两个入口）→ 两个都要 CSS 藏；③ 关窗**先 `view.save()` 再 `leaf.detach()`**，否则丢最后几秒输入；④ **同一时刻只开一个窗** —— 两个窗各自 save，谁最后写谁赢。另外：属性行可能有十来个，**面板要限高**（`min(78vh,760px)` + 中段可滚），不然正文编辑器被挤出屏幕（真机截屏才看出来）
- Templater 只在**剥掉前言后正文为空**时套模板、**先等 300ms** → 与"新建就写盘"是抢写关系
- **内嵌图谱（S1 已验证可行）**：`new WorkspaceLeaf(app)` + `setViewState({type:'graph'})` + 把 `leaf.view.containerEl` 挂进自有容器 —— canvas **立刻有尺寸**、不占标签页、`detach()` 后渲染循环真停。三个坑：① 容器**自带 `.view-header`**（图谱的过滤滑杆住在里面）必须 CSS 藏 → 注入过滤只能走 `graph.json`；② **核心插件被关掉时 `getViewType()` 仍返回 `'graph'`** → 必须**挂之前**读 `internalPlugins.plugins.graph.enabled`；③ 内嵌视图的 `data-type` 不是工作台 id → 用 `[data-type="<自注册id>"]` 做作用域会**真机零命中**（离线测试假绿的经典来源）
- 🔴 **平台的 `View.close()` 是「先摘 DOM、再 `await this.onClose()`」**（d2 从 asar 逐字节取证）：
  `t.prototype.close = function () { … this.containerEl.detach(), this.unload(), [4, this.onClose()] … }`。
  于是**视图 `onClose()` 跑的那一刻，`contentEl` 的后代已经不在文档里了** ——
  凡是用 `isConnected` 判"还开着吗"的关闭短路（`ui/panel.ts` 的 `close()` 就是），
  在这一刻会把**整段收尾**（save + detach 每个叶、dispose 监听、component.unload）全跳过。
  浮层态之所以没露出来，只是因为 root 挂在 `document.body` 上。**改用显式 `closed` 标志。**
  ⚠️ 而且**桩原先把这个顺序写反了**（先 `onClose` 再 `remove`）→ 这条离线恒绿：
  "桩比真机宽松 = 假绿"的第 N 次复发（`tests/stub` 里那条注释写了取证全文）
- ⚠️ **平台自己的编辑器会在视图关闭时把 buffer 存掉**（d2 实测：`detach()` 之后 **158ms** 落盘，
  与我们有没有调 `save()` 无关）⇒ **"读文件看变没变"验不出"我们有没有 save"**。
  这条差点让一条真机判据变成"永远不会红"的假绿（在带缺陷的构建上照样绿）——
  涉及"关窗时有没有保存"的判据只能落在离线那一层（前提是桩与平台对齐）

## 二、高价值八条（先看这个）

> （并入自开发期用的平台 skill，原文未改 —— 下面这八条是 39 条全表里最高频的。）

按"撞上概率 × 排查耗时"排序。

1. **`Plugin.saveData` 会静默吞掉失败**（吞 ENOENT）。往插件目录的子路径写 `data.json` 前必须先 `ensureFolder`，或者写完回读校验。否则症状是"存了像没存"且没有任何报错。不知道自己踩了这个坑，能查很久。

2. **`registerBasesView` 撞名不覆盖，只弹错**：`Unable to add new Bases view "<id>". A view with this ID already exists.`。而 `Plugin.registerBasesView` 内部用的是 `this.register(() => bases.deregisterView(id))`，`register` 挂在 `Component._events` 上——**`deregisterView` 只在 `load()`/`unload()` 执行**，只调 `onload()`/`onunload()` 时永远不跑。所以注册前必须自己先 `deregisterView` 同名 id 兜底。

3. **`renameFile` 就地改 `entry.file.path`**。改名或搬移前**必须先抄下旧路径**，事后再读 `file.path` 拿到的已经是新路径（`from === to`）。做"改名后保持排序/引用"这类功能时会静默失效。

4. **`fileManager.processFrontMatter(file, fn)` 是改属性的唯一可靠路径**：它是公开 API，走 vault 队列 = 原子。在多同步客户端（云盘 / OneDrive / iCloud）的库上尤其重要——直接用 `vault.modify` 拼 YAML 会和同步冲突。

5. **写盘要防抖 + 原子写**。双同步库下，就地编辑必须防抖（失焦或静默 1.5 秒），并用 `vault.process`；否则同步客户端会在你写一半时插进来。

6. **`fileManager.trashFile` 不弹确认框**（1.13.7 实测），它按 `vault.getConfig("trashOption")` 分流到系统回收站 / 本地 `.trash` / 永久删。所以**批量删除要自己加确认**，并走 `trashFile` 而不是裸 `vault.delete`——前者尊重用户设置。

7. **"受限模式"不在 `.obsidian/` 里**。它的实现是应用级 localStorage：`localStorage.getItem("enable-plugin-" + appId)`，位于 `%APPDATA%\obsidian\Local Storage\leveldb`。往库里写 `community-plugins.json` 只能决定"启用哪些插件"，**关不掉受限模式**——只能让用户在界面上点一次"开启社区插件并重载"。别白费力气想办法程序化绕过。

8. **Templater 只在"剥掉前言后正文为空"时套模板**，且**先等 300ms**。任何"新建笔记就写盘"的插件都是和它抢写：先写前言会让模板不触发，谁先写谁定局。要协作就自己延迟等待，并且**先落空文件**。

### A. Bases / 视图系统

1. 🔴 `Plugin.registerBasesView(id, reg)` 的实现体是 `bases.registerView(id, reg)` + `this.register(() => bases.deregisterView(id))`。`this.register` 挂在 `Component._events` 上 —— **`deregisterView` 只在 `load()` / `unload()` 执行**。只调 `onload()` / `onunload()` 时它永不跑，视图 id 会一直留在注册表里。再次注册前必须自己先 `deregisterView` 同名 id 兜底。

2. 🔴 Bases 的 `registerView` 遇到同名 id **不覆盖**，只弹错：`Unable to add new Bases view "<id>". A view with this ID already exists.`

3. `registerBasesView` 是 1.9+ 的半公开 API，依赖核心插件 Bases 已启用。不可用时视图类型**不出现在「视图布局」下拉里**（不报错，只是消失）——排查时别往"代码写错了"方向找。

4. **视图注册必须同步放在 `onload` 第一件事**。`onload` 里若先 `await`（如 `await loadSettings()`），会把 `registerBasesView` 排进微任务。Obsidian 会 `await onload()`，生产环境等价，但时序不可见，调试时容易误判。

5. **`.base` 视图块里的非已知键会被原样回写**：`BasesViewConfig.serialize()` 内为
   `if (this.data) for (const k of Object.keys(this.data)) this.hasOwnProperty(k) || (e[k] = this.data[k]);`
   → **插件自定义配置存进视图块是官方支持的行为**：配置随 `.base` 走、能手工改、能进版本控制、能分享。
   已知键只有：`type / name / filters / groupBy / summaries / order / sort / limit`。

6. 视图配置读写 `config.get(k)` / `config.set(k, v)` 是内部实现：`set` = `this.data[k] = v; this.query.save()`（`null` = 删键）。失效表现是「面板改不动 / 配置重启后丢失」，不是崩溃。

7. 原生视图选项描述符是**扁平**结构：`{displayName, type, key, default, min, max, step, options, shouldHide}`，Bases 逐条渲染成「标签 + 控件」**一行**。**描述符里没有行分组概念**——滑杆和开关合不进同一行。`getViewOptions(config)` 会收到 config（核心 list 视图靠闭包吃它实现 `shouldHide`）。

8. 视图选项可用控件类型只有 **10 种 + property**：`toggle / dropdown / text / textarea / number / file / folder / slider / color / secret`，外加 `property`（**单选**属性选择器）。**平台没有多选控件**——想要多选只能自研 UI。

9. 🔴 视图拿数据的唯一来源是 `this.data.data`（Bases 查询结果，条目形状 `{file, frontmatter, getValue(id)}`）。**笔记属性里没有「正文」**——`BasesEntry.FILE_PROPERTIES` 只有 14 项，不含正文。想在视图里显示正文只能自研渲染（`vault.cachedRead` + 自己剥前言）。视图的配置面是 `v.config = {get/set/getOrder/getSort/query:{save}}`。

10. 内部取值 API（asar，升级即可能失效）：`data.groupedData`（原生 groupBy 结果）、`entry.getValue("formula.<名>")`、`config.query.formulas` / `entry.formula.keys()`、`metadataCache.getAllPropertyInfos()` → `{小写名: {name, occurrences, widget}}`，widget ∈ `text|number|checkbox|date|datetime|tags|aliases|multitext|file|folder`。

11. 🔴 Bases 视图链（`contentEl` / `.bases-view`）**没有容器查询上下文**。Obsidian 自己用 `.bases-header{container-type:inline-size}` + `@container(width<540px)`。插件若自己给容器加 `container-type`，**会改变 `position:fixed` 后代的包含块**——风险很高，别随手加。

12. Bases 顶栏那个下拉**不是 `Menu`**（是内部建议框），类名锁在闭包里，**没有任何官方扩展点**。Bases 插件实例只暴露五个方法：`registerView / deregisterView / getRegistrations / getRegistration / getViewFactory`。往 `.bases-toolbar-menu` 注入 DOM 属「结构匹配」，改版即失效——要做就做成可关的实验开关，别当主入口。

13. 🔴 打开 `.base` 的 leaf，其 `data-type` = `View.getViewType()` = **原生 `"bases"`**，**不是** `registerBasesView` 注册的 id。用 `[data-type="<自己注册的id>"]` 做作用域会**真机零命中**（离线测试假绿的经典来源）。

14. 原生 `@container (width<540px)` 对 Bases 顶栏只把 `views-menu` 与 `result-count` **之外**的项收起——视图名按钮与「N 个结果」恰恰被留下。移动端面包屑：`.view-header-title-parent` 每段是独立元素，且自带 `:empty{display:none}`，末段的**文件名不是 parent**。

15. **原生 `groupBy` 是平的一层**，无自定义组序；`newItemFolder` 是 **base 顶层**的，一个 `.base` 只能配一组 → 「按分组落到不同目录新建」做不到，必须自己算落点。

### B. 文件与元数据 API

16. 🔴 `Plugin.saveData` **静默失败（吞 ENOENT）**：往插件目录下的子路径写 `data.json` 前必须先 `ensureFolder`，或写完回读校验。否则「存了像没存」，无任何报错。

17. `fileManager.processFrontMatter(file, fn)` 是公开 API，走 vault 队列 = 原子。**多同步库下改属性的唯一可靠写路径。**

18. 🔴 `fileManager.renameFile(file, absNewPath)` 是公开 API（双链更新由 Obsidian 负责），但它**就地改 `entry.file.path`** —— 改名/搬移前必须**先抄下旧路径**，事后读 `file.path` 拿到的已是新路径（`from === to`）。

19. `fileManager.trashFile` 读 `vault.getConfig("trashOption")` 分流到系统回收站 / 本地 `.trash` / 永久删，**且不弹确认框**（1.13.7）。批量删除应走它而不是裸 `vault.delete`，但**确认要自己加**。

20. `MarkdownRenderer.render(app, md, el, sourcePath, component)` 的第 5 个参数**必须是 Component**。传错或不传，核心会从插件栈帧报**内存泄漏告警**。

21. `metadataCache.getFileCache(f).frontmatter` 只在正文有合法前言时才有；`getFrontMatterInfo(md).contentStart` 可用于判断「剥掉前言后正文是否为空」；标签用 `getAllTags(cache)`（拿不到时退回前言 `tags`）。

22. `.base` 文件**不进 `.md` 索引** → 指向 `.base` 的链接会被知识库健康检查**误报为失效链接**。

23. 🔴 `TextComponent.onChange` 挂在 **`input`** 事件上 = 每按一个键回调一次。回调里若整页重画（`display()`）就会换掉输入框元素 → 焦点丢 → 下一个字符落空。**症状是「一次只能打进去一个字符」**，极易误判为输入法或键盘问题。

24. Obsidian 的 `Setting` 组件**根元素自带 `setting-item` 类**——DOM 过滤和样式断言按它选，别自造容器类。

25. Obsidian `Plugin` 是 ES class：继承必须 `class X extends obsidian.Plugin`。`.call(this)` 直接 TypeError。

### C. 插件生命周期与配置落点

26. 🔴 「受限模式」**不是 `.obsidian/` 里的文件**。本体实现：
    `PluginManager.prototype.isEnabled = function(){ return "true" === localStorage.getItem("enable-plugin-" + this.app.appId); }`

27. 🔴 `manifest.id` **必须等于插件目录名**。往 `.obsidian/plugins/` 下任意目录写 `data.json` 会造出「目录在 = 已安装」的**假插件目录**——插件列表里不显示，但同步客户端会把整个目录**同步复活**。

### D. 编辑器 / 视图装载

30. 就地挂编辑器（半公开：有导出但无文档）：`new WorkspaceLeaf(app)` + `new MarkdownView(leaf)` + `openFile`。挂上去的 `view.containerEl` **自带 `.view-header`**（会冒出一整排 `← → 标题 🔗 ⋮` 导航条），必须用 CSS 藏。构造失败要 `detach()` 已建 leaf，不留悬挂。

31. 🔴 `loadFile` resolve 的**那一刻 CodeMirror 还没排版**（`scrollHeight ≈ clientHeight`）→ 一次性算 `scrollTop` 恒为 0。**这是真机"滚动跳顶"的真正根因**。必须**轮询等 `scrollHeight > clientHeight`** 再落位；且重画后「视口上方」的懒加载内容长高会让**像素回填失效**，需改用元素锚点。

### E. 样式与容器

33. 🔴 改 Obsidian 原生控件外观前**必须先从 `obsidian.asar` 抓原生 CSS**，别靠肉眼量像素。例：原生 `.checkbox-container::after` 自带 `margin: var(--toggle-s-border-width) 0 0 0`，**关闭态**还有 `transform: translate3d(var(--toggle-s-border-width),0,0)` —— 只覆盖 `top/left/width/height` 会让圆点被顶下去又被右推。手搓 `<label class="checkbox-container">` 拿不到 `ToggleComponent` 自己加的 `.is-enabled`，必须 `:has(input:checked)` 兜底。

34. 🔴 原生 `input[type=range]` 选择器特异性 (0,1,1) 会**整条压掉**裸类选择器 (0,1,0)（height→4px、thumb 偏移叠加）。原生 range 的 **intrinsic 宽是 129px**，在 shrink-to-fit 浮层里光给 `flex:1 1 80px` 没用（max-content 阶段按 intrinsic 算），必须再给 `max-width` 封顶。

35. 原生 `@container (max-width:400px)` 会把 `.setting-item` 竖排 + 按钮 `width:100%`（特异性 (0,3,1)/(0,4,1)）—— 这是「窄屏按钮把文字挤到上面」的根因。要压回去得用更高特异性，不必 `!important`。

36. 🔴 手机**横屏**宽度 844~932px > 700px → 写在 `@media (max-width:700px)` 里的尺寸规则在横屏**永不命中**。手机端规则应挂 `body.is-mobile` / `.is-phone`，**不按视口宽度判**。
    触屏「点完还留着悬停态」要**让规则不加载**（顶层 `:hover` 就地包进 `@media (hover: hover)`）；补 `@media (hover:none)` 复位名单是追不完的。
    触屏 `:active` **只改颜色，不改尺寸/位移**——否则点下去卡片会跳一下。

37. 移动端：`manifest.json` 需 `isDesktopOnly: false`，且桌面专有 API 必须能力探测 + 守卫。

### F. 第三方协作（Templater）

38. 🔴 Templater 的 `on_file_creation` 只在「剥掉前言后正文为空」时才套目录模板（**先等 300ms**）。与任何「新建笔记就写盘」的插件是**抢写**关系：谁先写谁定局。
    **先落空文件**，别先写前言——先写前言会让模板不触发。
    模板文本含 `<%` 时必须先交 `parse_template({template_file, target_file, run_mode:0, active_file}, 全文)`（run_mode 0 = CreateNewFromTemplate）求值再落盘；求不到就**拒写**。直接落原样会让 `---` 不在第 1 行 → Obsidian 不认前言 → 标签/属性全废。

### G. 工作区 / 标签页层

39. 🔴 **`Esc` 会把主区里"另一个标签"切成活动叶 —— 自定义视图当场 `display:none`、几何全变 0**（1.13.7 真机逐帧实测，非 asar）。
    `Keymap.handle()` 对 escape **只问分层栈**：你的视图没压 Esc 层时没人接 → 事件落到**平台层** → 平台把主区里另一个标签（例如一篇 markdown）激活 → 你那一页 `display:none`。
    之后 `getBoundingClientRect()` **全是 0**，看起来像"这个视图坏了"（真机上表现为"卡片不在视野里（rect [0,0,0,0]）"）。
    实测链子（主区 = 自定义视图 + 一个 markdown 页）：`点视图内部 → root=1463、activeLeaf=自定义视图` → `按 3 次 Esc → root=0、activeLeaf=markdown` → `再点视图内部 → 又回 1463`。
    ⇒ **任何"先连按 Esc 清浮层、再量几何"的代码 / 自动化脚本都不可靠**（量到 0 会被误读成"功能坏了"）。
    修法：量几何之前先 `workspace.revealLeaf(你的 leaf)`，**取基准值之前**就要做。
    ⚠️ `revealLeaf()` 之后 `workspace.activeLeaf` 可能仍报别的视图（实测它没跟着变），但**几何是对的** —— 所以判据要量几何，别信 `activeLeaf`。
    ⚠️ 推论：祖先 `display:none` 会把一切几何判据静默变成 0 —— 只有上界的比较（`h <= 40`）会**空过**，所以几何判据一律写成双边（`> 0 && <= 40`）。

## 四、构建与部署

> （并入自开发期用的平台 skill，原文未改。⚠️ 本仓的实际部署走 `scripts/deploy.mjs`，
> 口径见本仓 `README.md` 与 `CLAUDE.md` 红线。）

Obsidian 只认 `.obsidian/plugins/<插件id>/` 下的三个文件：`main.js`、`manifest.json`、`styles.css`。那是**运行位置**，不是开发位置——源码放哪都行。

推荐把源码放在库外（vault 外），构建产物再部署进去：

```
<源码目录>/                    ← git 仓库在这里
├── src/
├── manifest.json
├── esbuild.config.mjs
├── package.json
└── styles/                    ← 源码 CSS（合并/编译后产出 styles.css）

构建产物 →  <vault>/.obsidian/plugins/<id>/
```

**为什么源码放库外**：如果库挂着同步客户端（云盘 / OneDrive / iCloud Drive），开发时的构建噪声会进同步流；放库外还能一条命令同时部署到多个 vault（沙盒 + 正式）。

**必须遵守的两条约定**：

- **`manifest.id` 必须等于插件目录名**。往 `.obsidian/plugins/` 下任意名字的目录写 `data.json` 会造出"目录在 = 已安装"的假插件目录——插件列表里不显示，但同步客户端会把整个目录同步复活。
- **vault 根目录不要开 git 仓库**（仓库只开在源码目录）。库根有仓库会让 Obsidian 与同步客户端都难受。

**生效时机**：改 `main.js` / 插件 `data.json` 后必须**关掉再打开插件**才生效；改 `.base` 文件后必须关标签重开或 `Ctrl+R` 才重新实例化视图。

⚠️ **部署给用户的收尾语必须带"请 Ctrl+R 重载"**（P7.23 实测教训：用户报的两件"故障"——拖动浮标不跟手 + 旧右键菜单——全是**部署后未重载**、旧构建在内存里；部署脚本自己会打印这句，人转述时别省）。

标准 esbuild 配置要点：`format: "cjs"`、`platform: "browser"`、`external: ["obsidian", "electron", ...builtins]`、`target: "es2018"`、`bundle: true`。`obsidian` 包只提供类型，运行时由宿主注入，**绝不能打包进去**。

## 五、验证（类型检查 / 离线 DOM / 真机）

纯靠正则扫源码抓不到"改完当场抛异常"。分层验证：

1. **类型检查**（`tsc --noEmit`）——最便宜，先跑
2. **离线 DOM 冒烟**：jsdom + 桩 obsidian API + 真 `main.js`。能抓出大部分渲染和事件错误
3. **真机手测**：样式、拖拽、触屏、位置计算这类必须真机

离线 DOM 验证的两个关键陷阱：

- **harness 的 DOM 必须镜像真机容器属性**。例如打开 `.base` 的 leaf，其 `data-type` = `View.getViewType()` = 原生 `"bases"`，**不是**你注册的视图 id——用 `[data-type="<自注册id>"]` 做作用域会真机零命中（假绿）。
- **必须走真挂载链**，别手动调你自己新写的函数。手调 = 假绿：函数本身是对的，但真实调用路径没走到它，这类 bug 会被完全掩盖。

jsdom 的 `getBoundingClientRect` 恒返回 0，量几何前要用 `defineProperty` 覆盖成普通属性。

## 七、P7.3c 期补记（2026-10-02）：流式用量字段 · 网关的两种不认法

- ⚠️ **`stream_options: {include_usage: true}` 不是每家都认**（OpenAI 兼容口的一个可选扩展）：
  认不出的网关有两种表现 —— **忽略它**（末尾不发 usage 块 → 我们回落本地字符估算）或
  **直接 400**（把未知字段当错误）。两种都接住了，但接法是**分开的**：
  400 那条走的是"一个增量都没吐时的降级"（记下这个 baseUrl、改走整包），而
  **401/403/429/5xx 不许跟着降级** —— 换条路也一样失败，降级只会白打一次注定失败的请求。
  判据要按状态码分开写（只认 400 那一种），别写成 `status >= 400`。
- ⚠️ **用量块常常是"`choices` 是空数组、只有 `usage`"那一块**：SSE 的 `handleLine` 里
  如果先判"没有 delta 就 return"，这一块会被**静默跳过**（token 数永远拿不到，而功能看着正常）。
  收 usage 必须排在"delta 为空就 return"**之前**。

## 八、P7.18b2 期补记（2026-10-09 晚）：**重启后首段，空值属性格没有可编辑输入组件**

- 🔴 **真机实测**（用户四条对照实验定出来的）：`fileManager` 属性面板里，**空值 multitext
  （`文件位置:`（null））在"Obsidian 重启后、任何一次新建/重开页面之前"被渲染**时，
  那一格里**没有 `.multi-select-input`**（只有行壳/占位）；**做过一次新建笔记、或把页面
  关掉重开一次之后**渲染的格子才有 —— 即"**DOM 形态由页面渲染时刻决定**"，且已渲染的
  页面**不会自愈**（要关页重开）。
- 后果（当时的形状）：`ui/native-position.ts` 的钩子**只认 `.multi-select-input`**
  → 重启后点格落空、**没有任何反应**（静默退化），用户体感 = "选文件夹并移动"没了；
  重载插件治不了（页面不重渲染），"新建一篇"或"关页重开"能治（下个渲染才带输入组件）。
- **修法（P7.18b2）**：`cellInputOf` **放宽到整格** —— 认 `data-property-key="文件位置"` 的
  `.metadata-property`；格内有输入就用输入（"敲字直接打"不变）、没有就返回格子本身 ——
  "点哪都弹"。用户真机验收："正常了"。
- ⚠️ **推论**（以后钩平台属性区都照这条）：**认"格子"比认"格内的输入控件"稳** ——
  依赖属性区子元素（input/pill/建议列表）的钩子，都要考虑**重启首段的懒渲染形态**。
