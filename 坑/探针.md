# 探针（CDP · 真机）

CDP 真机验证与排查。修改探针后运行 `npm run lint:probe`。

### 早期（P0–P4.5 期间积攒，原清单这一段没有期号横幅）

- 🔴 **探针步骤是"共享一个窗口"的**：① 每步开始前先把上一步漏关的浮层收干净（P3 实测：设置面板没关 → 后面 P1 拖拽的指针全打在面板上）② 多个模态叠加时**取最后一个**（`lastModal`）③ 窗口小于 1400×900 要先放大、并清掉挤窄工作台的标签页 —— 工作台窄到 <640 就是"窄档"，**目录树会被 CSS 藏起来**，依赖"拖到树节点"的步骤必然假红
- 🔴 **刚 `probe:launch` 起来的第一次跑容易抖**：窗口/布局还在 settle，「悬浮小窗」「跨板块拖动」这类依赖坐标的步骤会红（2026-09-25 实测：冷启动首跑 8/10、复跑 10/10）。**复跑一次再下结论**，别急着改代码
- 🔴 **探针自造的临时文件一律带 `__探针`（双下划线）**：自清理靠这个标记认自己造的日志，写成单下划线会一轮轮攒下来
- **超宽元素不能取"几何中心"**：表格行可能 3000px 宽（列多了要横向滚动）→ 中心点在视口外 → `elementFromPoint` 返回 `null`（探针的右键与拖拽都因此失效过）。取**左侧可见区域的中点并夹进视口**
- **`String.raw` 模板里的注释不许出现反引号**：探针的 `HELPERS` 是 `String.raw\`...\``，注释里写 `` `foo()` `` 会**提前结束模板** → 整个脚本语法错误（P1 踩过两次；写注释用「」）
- **探针专坑（P4 又踩三个）**：① 菜单项是 **`div.kbw-menu-item` 不是 `button`** —— `clickByText` 点菜单会**静默点空**（"改设置没生效"其实是没点到），要用 `clickMenu`/`lastMenu`；② `center()` 每次都 `scrollIntoView` → "先取目标点再取源点"会把源点坐标**做废**（拖动"拖了个寂寞"）→ 要两个点同时在视野就用不滚动的 `rectAt`，顺序是"先滚目标、再滚源、最后各取一次"；③ **库内配置让步骤互相污染**：看板配置.json 上一轮留下的档位/板块会让下一轮假红（只属性档没正文、残留板块让卡片数翻倍）→ 每步开始自己把状态拨回基线，**早退之前也要清场**（第一轮就是这么把 `__探针*.md` 留在库里的）
- 🔴 **探针专坑 ④：窗口不可见 / 没有焦点**（2026-09-25 实测，一次抓出两类假绿）：
  · **窗口被最小化或遮住** → `document.visibilityState === 'hidden'`，此时 **Chromium 给所有元素 0 几何** → "有没有横向溢出"这类判据**空过**（0 ≤ 0 恒真）、量宽高的判据则莫名其妙红。**`Page.bringToFront` 之后立刻恢复正常**（实测 hidden→visible、几何 0→256）。
  · **窗口可见但没有焦点**（被别的窗口压着）→ 几何是好的，但**Chromium 不为后台窗口产出新帧** → `Page.captureScreenshot` 会给一张**陈旧的**画面（实测拿到过一张"收起态画成整宽横头"的图，而同一刻 DOM 明明是 40px 竖条）。**截图只当辅助证据，几何判据一律看 DOM 测量**。
  · 推论：判据里写 `height <= 40` 这种**只有上界**的比较，遇到"量到 0"会**假绿** → 几何判据一律写成**双边**（`> 0 && <= 40`）。
- ✅ **"最小化也能验证/开发"已经做掉**（用户 2026-09-25 要的）：窗口不可见时，**探针与 peek 自动切模拟视口**
  （`Emulation.setDeviceMetricsOverride` 1400×900）—— **几何与输入都照常**（实测：最小化状态下全量探针 51 步里
  47 步通过，含全部拖动/几何步骤；剩下 4 步就是下面那条截图）。
  ⚠️ **截图是唯一拿不到的**：最小化/被遮住时 `Page.captureScreenshot` 会**超时**（`fromSurface:false` 也一样 ✗），
  所以"要截图证据"就得让窗口不最小化（`KBW_LAUNCH_MIN=0 npm run probe:launch`，或手动点开）。
  截图失败**不再把整轮带崩**：记一条 `📷 截图失败：…` 继续跑（它只是证据，不是判据）。
  `npm run probe:launch` 起来之后会**自动把它最小化**（`ShowWindow(SW_MINIMIZE)`；启动参数那两条路实测都不行：
  `Start-Process -WindowStyle Minimized` 这个 app 根本起不来、`cmd start /min` 会被 Obsidian 自己的窗口状态覆盖。
  CDP 也没有窗口状态域：`Browser.getWindowForTarget` 在页面连接与浏览器连接上**都没有**）。
  想直接看界面：`KBW_LAUNCH_MIN=0 npm run probe:launch`。
- 🔴 **探针专坑 ⑤：`Input.dispatchMouseEvent(mouseWheel)` 只派事件、不产生滚动**（2026-09-25 实测）：
  事件到了、没人 `preventDefault`、可 `scrollTop` 还是 0 —— 我差点据此去改代码。**真滚动要用
  `Input.synthesizeScrollGesture`**。一句话：**测处理器用 --wheel，测滚动用 --scroll**。
- 🔴 **`window.resizeTo` 在模拟视口下失效** → 任何"缩小窗口看窄档"的步骤都要改成**声明视口**
  （probe 的步骤写 `viewport: [600, 820]`，runner 用 CDP 设/收；两种状态下都生效且尺寸可复现）。
- ✅ **探针的逐步自清理一定会漏**（d2 查清的老账）：`P.sweep()` 靠作者记得调，实测至少漏了一步（`P4.5 · 拖动落点` 的 `cleanup()` 从不 sweep）→ 每跑一轮攒一条日志 + 一份快照（实验库里积了 38 份）。现在 `probe.mjs` **跑完按标记兜底清场**（日志正文含 `__探针` + 日志里点名的快照），认标记**不是**"与开工前 diff"

### f 期（2026-09-26 晚）新增的：多悬浮窗 · 每篇小窗设置 · 字号 · 尾链折叠

- ⚠️ **单篇的窗没有「全部关闭」**（tab 条 ≥2 篇才画）→ 关窗/收尾要退到面板底部的「完成」。
  只认一个按钮必漏（真机探针 `closeEditPanel` 与本期的离线用例各栽过一次）。
- ⚠️ **`lastMenu()` 会拿到别的子菜单**：菜单是**叠着**的，展开过的兄弟子菜单**留在 DOM 里** ——
  点子菜单项要"从后往前找**装着这一项的那一层**"（`probe-helpers` 的 `clickAny` / `clickMore`），
  否则静默点空、菜单留在屏幕上挡住后面所有步骤。
- ⚠️ **小窗会盖住"被点那一列的头几张卡"**（它就开在那儿）→ 探针里"右键某张卡"的步骤必须先确认
  那一点**真的命中卡片**（`elementFromPoint`），必要时**把小窗拖开**再点。字号变大之后这一条更容易撞上。
- ⚠️ **开发/探针留下的临时标签页会污染后面的判据**：一个多余的 markdown 标签会让 `Esc`
  落到平台层 → 平台切到另一个标签 → 工作台 `display:none` → **所有几何量到 0**（症状像"卡片不在视野里"）。
  spike 完当场关掉自己开的标签。
- ✅ **面板头可以拖**（`ui/panel.ts` 的 dragHandle）：探针/用例里"小窗挡住目标"时，最省事的解法是
  把它**拖开**——pointerdown 打在 `.kbw-panel-head`、move/up 打在 `document` 上（拖动基元就是这么听的）。

### P6 期（2026-09-27）新增的：网格档 + 图谱（第一段）

- 🔴 **探针步骤之间的"视野"是会话态，会互相污染**：搜索框内容、`filters.paths`（快速切换跳一篇时会设）、
  目录树选择（**落盘**）都会被前面的步骤留在半路 —— 症状是网格只剩**一格/一行**，
  而报出来的是"窗口太窄？"（真正的起因在十几步之前）。开场用 `P.scopeAll()` 摆好：
  清搜索 → 清筛选 → 点「整个知识库」→ 切网格。
  ⚠️ 而且**切模块回来会被"待消费的意图"重新应用一次**（`mount()` 里那段），所以"切走再回来"清不掉它。
- 🔴 **截图是脚本返回之后才拍的** → 收尾要是把界面切走了，拍到的是**别的屏**
  （实测拿到过一张表格，而这一步测的是图谱）。要拍哪一屏就**最后停在那一屏**。
- **别用"数页面的 rAF"判某个视图的渲染循环停没停**：自己排一条 rAF 链量到的是**整页帧率**，
  挂载中 98、切走后还是 98（实测）—— 看起来像"没停"，其实什么都没测。
  真实信号是**那个渲染器自己的空闲帧计数**（`renderer.idleFrames` 在涨 / 不涨）。
- **探针动过的界面偏好要拨回基线**：视图档 / 顺序表 / 自动排列都是**落盘的**，
  探针把它们改成"网格 + 一长串手排顺序"之后，下一轮跑起来时「P1 · 全部笔记」会看到一张
  **没有行的表格**（整片假红，失败点看着与网格毫无关系）。开场记一份、收尾原样还回去。
- **几何判据在"拿不到视图实例"时不许降级成通过**：图谱的"渲染循环停没停"我先写了降级
  （`idleMounted > 0` 才算数）——窗口不可见时它恒不成立，于是**一条真问题会被放过去**。
  降级要写清"这条判据此刻不成立"，而不是悄悄算过。

### P6 ③ 期收尾补课（2026-09-28）新增的：探针夹具 · 「量到 0」的根因 · 静默跳过

- 🔴 **`Esc` 会把工作台踢到后台 —— 历史上那一串"几何量到 0"的根因多半就是它**（逐帧验过）：
  工作台当时是**活动叶**时，按下的 Esc 若没人接（`P.closeAll()` 会连按 4 下）就落到**平台层**
  → 平台把**另一个标签**切成活动叶（实验库里就是上一篇 markdown）→ 工作台当场 `display:none`
  → 之后 `getBoundingClientRect()` **全是 0**。实测链条：
  `点看板后 root=1463（active=kb-workbench-view）→ 再按 Esc×3 → root=0（active=markdown）`；
  而"点一下工作台里的东西"又能把它切回来。**于是"closeAll 之后立刻量几何"在所有步骤里都不可靠**，
  症状是「第一张卡片不在视野里（rect [0,0,0,0]）」这种**看着像功能坏了**的谜面（本轮两条红都是它）。
  修法两处：① `P.closeAll()` 末尾就地 `revealLeaf(工作台)`；② runner 的每步前置**量一下再救**，
  救回来就**说出来**（沉默地救 = 下一次谁也看不见它又发生了）。
  ⚠️ 取基准宽度（`wbRect0`）之前尤其要救 —— 否则"分屏之后没被挤窄（0 → 578）"整条假红。
  ⚠️ 诊断一律走 `P.zeroGeoWhy(el)`（它一次报清：`visibilityState` / 焦点 / 藏它的那个祖先 / 活动叶）。
- 🔴 **判 PASS 的步骤，info 里那句括号话要当判据读**：`P6 · 网格档：拖动换位` 里"拖到目录树
  真搬文件 + 撤销"那一整段，是按「这一层里有一篇 **00_Inbox** 的笔记」找源格的 —— P6b ② 起列表
  **只画本层**、而本层是自造的 `__探针网格B` → **一个都命中不了、整段静默跳过、那一步照样写
  「全部通过 ✓」**（唯一的痕迹是 info 里那句「（没有 00_Inbox 的笔记可拖）」）。
  **要跳过就必须 `note()`/`bad.push()`**，不许只改 info 文案。修法：源格自造
  （`__探针网格迁.md`，**名字带标记** → 万一撤销没成，兜底清场能收走；用种子目录里的「笔记N.md」就认不出来）。

### P7.17 期（2026-10-09）：两个助手语义的坑 + 一枚真 bug

### P7.24 期（2026-10-11）：**探针步 finally 里 `settings.save` 不同步活模块 store —— 后续步别查 settings 判态，一律 DOM 自证**

- 🔴 **实测形状**（P7.24 · T2 步首次跑就栽）：前一步 finally 里 `ctx.settings.save({ treeOpen: open0 })`
  只把**落盘值**还原了；笔记模块的 store 是它自己一份（`main.ts` 的 `applySettingsToStore`
  只管 `activeModule / modules / lastSnapshotAt`，**树展开态不在内**）→ settings 说"根开着"、
  **DOM 里树还是收着的**。下一步若按 `settings.get().treeOpen` 判起手态（"开着就跳过点击"），
  就会在错误的基线上跑、断言整片反过来红（报的是"点根 caret 之后该只剩根一行（实际 7 行）"）。
- ⇒ **两条纪律**：
  ① 探针步的**起手态一律从 DOM 自证**（`aria-expanded` / 行在不在），**不查 settings 判**；
     要"点开一下"就点一下（幂等）。
  ② 步的 finally 里 `settings.save` 之后，若要给后续步留一个干净的树态，
     得**按目标态把 live 树点回来**（`aria-expanded` 比对 + 点根 caret），不能只 save。
- ⚠️ 同族提醒：这不是新 bug —— P7.23 的步也这么 restore 的，只是它们之后没有"信 settings"的步，
  潜伏没发作。凡是"前一步动界面态、后一步读界面态"的相邻步，都按本条走。
