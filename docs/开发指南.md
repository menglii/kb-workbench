# 开发指南

## 环境与首次运行

使用 Node.js 24 和 npm，在仓库根目录执行 `npm ci`、`npm run typecheck`、`npm run lint:probe`、`npm run build`。

`build` 生成 `main.js` 和 `styles.css`，不会部署到知识库。`watch` 持续监听源码和样式；核对精确构建指纹时使用一次性 `build`。插件运行时由 Obsidian 注入 `obsidian` 等模块，不能直接在 Node.js 中运行构建后的 `main.js`。

## 测试

`npm test` 和 `npm run test:shards` 任选一种运行全量，不要同时启动。普通全量使用固定临时路径，同目录不能并行启动两份；分片命令为各片隔离临时目录。合成夹具由测试工具生成，不需要真实笔记。

`npm run lint:probe` 只检查探针脚本；`npm run probe` 需要 Obsidian 测试环境，会真实交互并创建、清理测试数据。此次仓库整理未启动真机探针，也未部署到任何知识库。

在 Windows 上建议直接使用 Node.js 24。历史文档提到的本机工具链 shim 和绝对安装路径属于作者环境，不是其他开发者的安装前提。

## 安装到测试库

将 `main.js`、`manifest.json`、`styles.css` 和整个 `assets/` 目录复制到测试库的 `.obsidian/plugins/kb-workbench/`，再从 Obsidian 设置启用插件。更改产物后需要重新加载插件。

使用部署脚本前，请先配置环境变量：

| 环境变量 | 用途 |
| --- | --- |
| `KBW_VAULT_SANDBOX` | 测试知识库路径 |
| `KBW_VAULT_REAL` | 真实知识库路径；仅在明确决定部署时使用 |
| `KBW_OBSIDIAN_EXE` | 本机 Obsidian 可执行文件路径 |

详见 `scripts/vault-guard.mjs` 和 `scripts/probe-launch.mjs`。源码中的路径占位不能直接当作有效路径。对真实库部署必须显式指定并确认，首次体验建议手动复制到测试库。

## 打包与资料

分享和演示打包命令应显式传入 `--out` 指定输出目录。`pack:contest` 还依赖讲解页（`--html`）和官方安装器缓存或下载，不属于基础构建步骤。

从本公开仓库分享源码，可用 `node scripts/make-public-pack.mjs --out <输出父目录>`。它复制源码、配图和公开文档，排除依赖、测试临时目录和构建产物；目标 `kb-workbench` 已存在时拒绝覆盖。该工具检查常见凭据，不替代分享前的人工隐私审查，不应直接用于未经脱敏的私人工作目录。

资料入口见[文档目录](README.md)。不提交 `node_modules/`、构建产物、`.pack-cache/`、测试临时目录、真实笔记或 API key。
